# 작업 관리 화면

상태: 사용자가 React + shadcn/ui 조회용 화면과 GitHub 상태 스냅샷 방식을 승인했습니다. 구현은 dashboard/에 있습니다. 로그인·쓰기 서버·실시간 조회·상시 실행은 없습니다. [위임 범위](delegation.md)는 그대로 적용합니다.

사용자는 중요한 결정과 예외를 먼저 봅니다. 일반 작업은 에이전트가 처리하고, 완료 요약·검사·결과물·원문 링크를 남깁니다.

### 문제와 예외

실패한 검사, 반복 실패한 작업, 문서와 코드의 충돌을 보여줍니다. 자료가 없거나 갱신에 실패했으면 정상으로 표시하지 않고 마지막 확인 시각과 오류를 보여줍니다. 승인되지 않은 설계 질문과 실제 실행 실패를 구분합니다.

### 현재 기준

| 검사·수집 근거 | CI 실행·아티팩트·검토 기록 | 근거 위치와 확인 범위 표시 |

카드에는 대상 이슈·PR, 마지막 갱신 시각, 근거 링크를 둡니다. 에이전트의 요약과 실제 CI 결과를 구분합니다. GitHub가 닫힘이면 화면에서 진행 중으로 계속 남지 않도록 갱신하며, 조회 실패를 이슈 종료로 해석하지 않습니다.

## 첫 구현

React + TypeScript + Vite와 shadcn/ui Button을 바탕으로 만든 정적 화면입니다. GitHub API에서 만든 공개 상태 스냅샷을 읽고 한국 시간으로 생성 시각을 표시합니다. 실시간이라고 표현하지 않습니다. 토큰을 번들·HTML·상태 JSON에 넣지 않습니다. API에서 받은 제목·본문은 신뢰하지 않는 텍스트로 렌더링합니다.

승인·병합 버튼과 로그인·쓰기 서버·정기 실행은 후속 범위입니다. 문서 사이트는 계속 docs를 렌더링하고 관리 화면은 링크로 연결합니다. 범용 UI 라이브러리는 외부 DART MCP·래퍼를 쓰지 않는 결정과 별개지만, 이번 React·shadcn/ui 구현 도입은 사용자에게 확인했습니다.

## 완료를 어떻게 확인하나요?

- 사용자가 첫 화면에서 자신이 답할 질문과 이유를 찾을 수 있습니다.
- 완료 작업에서 PR·검사·결과물로 이동할 수 있습니다.
- 갱신 시각과 원본이 있어 오래된 상태를 구분할 수 있습니다.
- 사용자 확인 대상이 아닌 일반 작업에 매번 승인 카드를 만들지 않습니다.
- 키·내부 법인 목록·불필요한 원문 데이터는 화면에 싣지 않습니다.

## 실행과 갱신

Node.js 24와 GitHub CLI가 필요합니다. 저장소 루트에서 `cd dashboard`, `npm ci`, `npm run dev`로 엽니다. 정적 결과물은 `npm run build`가 만드는 dashboard/dist/입니다. 사용자는 Vercel 배포를 선택했습니다. Root Directory는 dashboard, 빌드는 npm run build, 출력은 dist, 운영 브랜치는 main입니다. 실제 배포 주소는 아직 확인하지 못했습니다.

`npm run snapshot`은 gh의 기존 인증으로 공개 이슈·PR·main 검사 상태만 읽어 public/data/snapshot.json에 저장합니다. 제목·번호·상태·원본 URL·시각만 허용하며 토큰·본문·사용자 정보는 포함하지 않습니다. 조회 실패는 비정상 종료하고 이전 자료를 유지합니다. 최대 최근 100건이며 한도에 닿으면 화면에 표시합니다. 검사 이력은 최근 10건이며 전체 이력은 GitHub 링크에서 확인합니다.

화면의 다시 읽기는 저장된 JSON을 다시 읽습니다. GitHub 자료 자체를 갱신하려면 스냅샷 재생성·빌드·배포가 필요합니다. 24시간이 지난 자료와 미래 시각은 주의 표시를 합니다. 이 기준은 작업 현황의 표시용이며 DART 공시 판단 기준과 무관합니다.

결정 카드는 기준 문서의 합의 상태를 수동 반영합니다. 현재 현금 조회 범위는 결정 완료입니다. 결정 내용이 바뀌면 기준 문서와 카드를 같은 PR에서 갱신합니다. 이슈 전체를 LLM으로 분류하거나 모든 예외를 자동 발견하지 않습니다.

## 검사와 현재 한계

기존 필수 code-quality에 UI 린트·Vitest·TypeScript strict·빌드를 추가했습니다. 기존 Python 검사와 docs 빌드는 유지합니다. Vitest는 누락된 자료, 출처·링크 검증, 오래된 시각과 후속 성공이 있는 과거 실패를 검사합니다. CI는 정적 결과물을 management-dashboard 아티팩트로 저장합니다. GitHub 원본의 향후 변경이나 문서·코드의 의미 일치를 증명하지는 않습니다.

브라우저 렌더링·실제 클릭·모바일 시각 확인은 지정 브라우저 도구가 없어 미확인입니다. 사용자가 선택한 Vercel의 실제 배포 URL과 배포 결과도 아직 확인하지 못했습니다. 반응형 CSS와 빌드 성공을 시각 검증 완료라고 표현하지 않습니다.

2026-11-20 사용자가 운영 화면 접속을 확인했습니다. 초기 단계에서는 상세 모바일·클릭 검토를 보류하고 데이터 계약·공시 검증을 우선하기로 합의했습니다. 이슈 #13은 종료했으며 UI 빌드·타입·핵심 데이터 CI는 유지합니다. 이는 에이전트의 브라우저 시각 검증 완료를 뜻하지 않습니다.
