# 작업 관리 화면 설계안

상태: 화면 구성을 설명하는 초안입니다. React 앱·서버·실시간 GitHub 연동은 아직 만들지 않았습니다. [위임 범위](delegation.md)는 합의한 기준이며 화면의 기술 선택과 배치는 조정할 수 있습니다.

사용자는 중요한 결정과 예외를 먼저 봅니다. 일반 작업은 에이전트가 처리하고, 완료 요약·검사·결과물·원문 링크를 남깁니다.

## 첫 화면 예시

아래는 어떤 정보를 보여줄지 설명하는 예시입니다. 실시간 운영 화면이나 자동 생성한 현황이 아닙니다.

### 내 결정이 필요한 일

**현금 조회의 기본 범위**

- 질문: 법인 자체와 자회사 포함 그룹 전체 중 어느 금액을 기본으로 볼까요?
- 추천: 법인 자체(별도·개별)를 기본으로 하고 연결은 선택할 수 있게 합니다.
- 이유: 법인 자체가 보유한 금액과 자회사가 포함된 그룹 금액은 다릅니다.
- 영향: 대상 문서와 조건을 충족하는 법인 목록이 달라질 수 있습니다.
- 근거: [현재 요구사항](requirements.md). 이 기본값은 아직 확정하지 않았습니다.

첫 버전은 원본 이슈·PR로 이동해 답변하는 링크를 둡니다. 화면에서 승인했다고 저장하는 기능은 아직 없습니다.

### 문제와 예외

실패한 검사, 반복 실패한 작업, 문서와 코드의 충돌을 보여줍니다. 자료가 없거나 갱신에 실패했으면 정상으로 표시하지 않고 마지막 확인 시각과 오류를 보여줍니다. 승인되지 않은 설계 질문과 실제 실행 실패를 구분합니다.

### 현재 기준

합의한 요구사항·위임 정책·설계 결정·테스트 기준을 원본 docs로 연결합니다. 별도 사본을 새 기준으로 만들지 않습니다.

## 정보의 원본

| 정보 | 원본 | 화면에서 하는 일 |
|---|---|---|
| 이슈·PR 상태, 커밋, CI | GitHub | 상태와 링크를 표시 |
| 요구사항·판단·위임 정책 | docs | 요약과 해당 절 링크 제공 |
| 질문·추천·이유·영향 | 이슈 또는 PR의 결정 요청 | 필요한 내용을 모아 표시 |
| 검사·수집 근거 | CI 실행·아티팩트·검토 기록 | 근거 위치와 확인 범위 표시 |
| 세션 간 다음 행동 | 작업 상태 | 원본과 연결, 오래되면 재확인 |

카드에는 대상 이슈·PR, 마지막 갱신 시각, 근거 링크를 둡니다. 에이전트의 요약과 실제 CI 결과를 구분합니다. GitHub가 닫힘이면 화면에서 진행 중으로 계속 남지 않도록 갱신하며, 조회 실패를 이슈 종료로 해석하지 않습니다.

## 첫 구현 후보

React + shadcn/ui의 조회용 화면을 후보로 둡니다. 정적 페이지로 시작한다면 GitHub API에서 만든 공개 상태 스냅샷을 읽고 생성 시각을 표시합니다. 실시간이라고 표현하지 않습니다. 토큰을 번들·HTML·상태 JSON에 넣지 않습니다. API에서 받은 제목·본문은 신뢰하지 않는 텍스트로 렌더링합니다.

승인·병합 버튼과 로그인·쓰기 서버·정기 실행은 후속 범위입니다. 문서 사이트는 계속 docs를 렌더링하고 관리 화면은 링크로 연결합니다. 범용 UI 라이브러리는 외부 DART MCP·래퍼를 쓰지 않는 결정과 별개지만, 실제 새 의존성 도입은 사용자와 확인합니다.

## 완료를 어떻게 확인하나요?

- 사용자가 첫 화면에서 자신이 답할 질문과 이유를 찾을 수 있습니다.
- 완료 작업에서 PR·검사·결과물로 이동할 수 있습니다.
- 갱신 시각과 원본이 있어 오래된 상태를 구분할 수 있습니다.
- 사용자 확인 대상이 아닌 일반 작업에 매번 승인 카드를 만들지 않습니다.
- 키·내부 법인 목록·불필요한 원문 데이터는 화면에 싣지 않습니다.

구현 전에 첫 화면 예시와 데이터 원본을 확인하고, 이후 이슈에서 UI·GitHub 상태 읽기·검증을 작은 단위로 구현합니다.
