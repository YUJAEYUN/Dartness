# HD건설기계 원본·정정 개발용 정답 사례

상태: 2026-11-23 공식 공개 다운로드에서 전체 본문 PDF와 원문 XBRL ZIP을 각각 확보해 대조했습니다. 이미 읽은 개발용 사례입니다. 원본 연결·금액 확인의 근거이며 자동 정정 연결기나 범용 XBRL 추출기의 정확도 검증 완료가 아닙니다.

## 전체 자료와 최소 증거를 구분합니다

전체 네 파일은 [별도 데이터 커밋](https://github.com/YUJAEYUN/Dartness/tree/943b6c96df7e786d505eedeec5488ed58109f166)에 보존했습니다. 데이터 브랜치는 data/correction-pair-64이며 main에 병합하지 않습니다. source-manifest.json에 공식 URL·수집 시각·파일 크기·응답 해시·XBRL ZIP 내부 각 파일의 해시를 기록했습니다.

| 버전 | 접수번호 / 본문 문서 번호 | 전체 PDF | XBRL ZIP |
|---|---|---|---|
| 원본 | 20260318001192 / 11140821 | 2,229,244바이트, 물리 페이지 811쪽 | 1,177,489바이트, 파일 7개 |
| 정정 | 20260602000456 / 11416776 | 2,302,539바이트, 물리 페이지 810쪽 | 1,109,231바이트, 파일 7개 |

공식 뷰어의 다운로드 화면이 연결하는 PDF와 IFRS 원문 XBRL ZIP입니다. OpenDART document.xml API가 반환하는 제출서류 ZIP을 받은 것은 아닙니다. PDF는 선택한 본문 전체이고 XBRL ZIP은 해당 재무정보 묶음 전체입니다. 별도 감사보고서 등 모든 첨부를 완전 수집했다거나 서로 다른 다운로드 형식의 바이트가 같다고 주장하지 않습니다.

처음 요청은 HTTP 200이지만 본문이 비어 있었습니다. 공개 다운로드 화면과 같은 세션·브라우저 요청 헤더를 사용한 뒤 정상 PDF/ZIP을 받았습니다. 크기·파일 형식·PDF 전체 텍스트 변환·ZIP 내부 CRC를 확인했고, 비어 있던 응답은 정답이나 성공 기록에 사용하지 않았습니다. API 키·시크릿·워크플로·권한을 바꾸지 않았습니다.

main에는 tests/fixtures/corrections/hd-construction-2025의 최소 증거와 expected.json만 둡니다. XBRL 발췌는 원본 바이트 구간을 묶은 별도 XML입니다. 원본 네임스페이스 여는 태그 아래 필요한 문맥·단위·14개 현금 사실을 조립했으므로 완전한 원문 파일로 부르지 않습니다. 원문 멤버 해시·바이트 위치·구간 해시·압축/발췌 해시를 따로 기록했습니다. PDF 텍스트 발췌는 pdftotext -layout으로 변환한 파생 자료이며 PDF 원본 바이트가 아닙니다.

## 원본 연결과 기간 정답

법인 코드는 01205842, 원본과 정정의 사업기간은 2025-01-01 ~ 2025-12-31입니다. [이전 조사](../correction-linking.md)의 양쪽 뷰어 본문 관계와 전체 PDF 표지·정정표를 함께 대조했습니다.

- 원본 표지: 물리 5쪽, 사업기간과 2026-03-18 제출일.
- 정정표: 정정 PDF 물리 5쪽, 정정일 2026-06-02, 대상 서류 사업보고서, 최초 제출일 2026-03-18.
- 정정 본문 표지: 물리 7쪽, 같은 사업기간과 원본 제출일 2026-03-18을 유지. **본문 표지 날짜를 정정 공시일로 쓰면 안 됩니다.**
- 정정표는 연결 주석의 연결대상기업 개요에서 디테일 태깅을 블록 태깅으로 바꾼다고 기재합니다. 이 문구만으로 현금 불변을 판단하지 않고 아래 실제 셀을 대조했습니다.

## 변경 전후 현금 정답

아래 금액은 각 PDF의 재무상태표 2025-12-31 열과, 같은 법인·일자·연결/별도 차원의 XBRL 현금 사실을 대조했습니다. PDF 표 단위는 천원입니다. XBRL 단위는 KRW이고 두 재무상태표 사실의 decimals는 -3입니다.

| 재무 범위 | 원본 PDF 물리 쪽 | 정정 PDF 물리 쪽 | 원문 숫자(천원), 두 버전 동일 | 정확한 원화 값 |
|---|---|---|---|---|
| 연결 | 73 | 75 | 337,873,166 | 337,873,166,000원 |
| 별도 | 219 | 218 | 69,787,650 | 69,787,650,000원 |

이 두 셀에 한해 값·기간·단위·범위를 대조해 같음을 확인했습니다. 정정 전후 모든 재무 항목·주석이 같다는 결론은 아닙니다. 두 전체 PDF·XBRL ZIP·인스턴스 해시는 서로 다릅니다.

각 XBRL 인스턴스에는 CashAndCashEquivalents 사실이 14개 있습니다. 본 사례에서 이 14개 사실의 문맥·단위·decimals·값을 대조하면 두 버전이 같습니다. 그 안에는 과거 기간과 추가 금융상품 차원, 백만원 정밀도로 표시된 사실도 있습니다. 같은 태그라고 같은 셀을 뜻하지 않습니다. 백만원 정밀도의 별도 69,788,000,000원·연결 337,873,000,000원은 현재 재무상태표 셀과 구분해야 하며 이 차이를 곧바로 잘못된 공시로 보지 않습니다.

현재기 재무상태표 사실은 법인 01205842·2025-12-31 instant·KRW이며 연결/별도 축 하나만 가진 문맥을 사용했습니다. 문맥 ID는 expected.json에 정확히 기록했습니다. ID 문자열만 해석하지 않고 실제 context의 법인·날짜·차원을 확인합니다.

## 검사 범위와 다음 구현

테스트 작성 전에 PDF 행과 XBRL 원문에서 위 정답을 고정했습니다. tests/test_correction_case.py는 다음을 검사합니다.

- 발췌 압축·본문 해시, context·unit·단위·기간과 고정 원화 정답의 일치
- PDF 파생 발췌의 기간·천원 단위·행과 XBRL 현재기 값 대조
- 과거·추가 차원·다른 정밀도의 사실이 함께 있음을 보존하고 14개 사실의 버전 간 비교
- 실제 접수번호·전체 PDF 해시를 사용한 기존 후보 계약의 공시 마감·근거 보존·복수 후보 보류

2026-05-01 실행을 가정하면 6월 정정은 선택 대상에서 제외됩니다. 2026-11-23 실행에는 두 버전이 모두 있어, 아직 연결기가 없는 현재 후보 계약은 ambiguous_candidate로 보류해야 합니다. **금액이 같다는 이유만으로 최신 정정을 자동 선택하게 바꾸지 않습니다.**

원본 관계와 두 셀의 동일함은 사람이/에이전트가 원문 대조로 확인한 정답입니다. 테스트가 이 관계를 자동으로 발견하거나 범용 XBRL 파서를 검증한 것은 아닙니다. 다음 구현은 명시적 원본 연결·항목 적용 근거를 받아 검증하는 계약이며, 다중 차수·철회·첨부정정은 미결 근거를 채우기 전까지 보류합니다. 기존 수집기·현금 추출기·날짜/후보 코드와 기존 정답은 유지합니다.
