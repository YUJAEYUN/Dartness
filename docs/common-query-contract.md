## 공통 입력 계약의 방향

| 필드 | 의미와 현재 결정 |
|---|---|
| 조회 유형 | 다섯 유형 중 하나. 미구현 유형을 현금 조회로 대신 처리하지 않음 |
| 법인 범위 | 기본은 실행일 현재 상장법인 전체와 세 시장. 지정 목록으로 좁히는 기능의 구체 형식은 후속 설계 |
| 조회 시점 | 금액·보유 상태는 최신 자료 또는 기준일 지정. 어느 모드도 임의 기본 선택하지 않음 |
| 요청 기준일 | 기준일 지정 모드에서 명시. 최신 모드의 계산 기준은 실행일이며 공시 제출일과 구분 |
| 대상 기간 | 사건 조회에서 명시할 시작·종료 범위. 주식보상·대출의 어떤 사건을 볼지는 유형별 미결 유지 |
| 최대 경과 기간 | 정확히 일치, 3개월, 6개월, 12개월, 직접 입력 중 선택. 직접 입력도 개월 단위이며 계산은 아래 규칙 적용 |
| 유형별 조건 | 금액·통화·자산 범위·당사자 역할 등 유형별 계약으로 검증. 아직 없는 기준을 채우지 않음 |
| 검토 내역 포함 | 기본은 끔. 켜면 확인 불가 법인과 이유를 별도 시트로 제공 |

입력은 한 유형을 명시하는 구조로 시작합니다. AND/OR 복합 조건·자동 유형 추론·모듈 등록 방식은 아직 구현하지 않았습니다. 같은 법인의 중복 상장·종목과 법인 식별을 구분해야 하며, 전수조사의 기준은 법인입니다. 모집단은 조회 실행일 현재 상장법인이며 요청한 과거 재무 기준일 당시의 상장 목록을 복원하는 방식은 기본으로 사용하지 않습니다.

## 조회 시점과 허용 기간

금액·보유 상태 조회는 다음 두 모드 중 사용자가 선택합니다. 사건 조회의 시작·종료 기간과 사건 의미는 별도 설계 대상입니다.

| 모드 | 계산 기준 날짜 | 선택할 자료 |
|---|---|---|
| 최신 자료 | 조회 실행일 | 실행일까지 공개된 자료 중 허용 기간 안에서 실제 자료 기준일이 가장 최근인 자료 |
| 기준일 지정 | 사용자가 지정한 기준일 | 해당 날짜 자료를 우선하고 없으면 허용 기간 안에서 가장 가까운 이전 자료 |

최신은 가장 최근에 제출된 문서를 뜻하지 않습니다. 최근 공시에 실린 과거 비교 수치와 최신 실제 기준일을 구분합니다. 두 모드 모두 지정한 재무 범위·항목·통화가 맞아야 하며 실행일까지 공개된 관련 최신 유효 정정을 적용합니다.

허용 기간은 정확히 일치 / 3개월 / 6개월 / 12개월 / 직접 입력으로 제공합니다. 직접 입력도 개월 수입니다. 시스템이 3·6·12개월 중 하나를 미리 선택하거나 자료를 못 찾았다고 기간을 늘리지 않습니다. 정확히 일치는 계산 기준 날짜와 실제 자료 날짜가 같아야 한다는 뜻입니다. 따라서 최신 모드에서 정확히 일치를 선택하면 실행일 당일 자료만 허용하며, 없으면 확인 필요입니다.

개월은 고정 일수가 아닌 달력 기준입니다. 계산 기준 날짜에서 선택한 개월 수를 한 번에 빼고, 해당 월에 같은 날짜가 없으면 그달 말일로 맞춥니다. 허용 구간은 시작일과 계산 기준 날짜를 모두 포함합니다. 매월 반복 차감해 날짜가 줄어들거나 월말을 무조건 유지하는 방식은 사용하지 않습니다.

| 계산 기준 날짜 | 사용자 선택 | 허용되는 실제 자료 날짜 |
|---|---|---|
| 2026-09-30 | 6개월 | 2026-03-30 ~ 2026-09-30 |
| 2026-08-31 | 6개월 | 2026-02-28 ~ 2026-08-31 |
| 2024-08-31 | 6개월 | 2024-02-29 ~ 2024-08-31 |
| 2026-09-30 | 정확히 일치 | 2026-09-30만 |

예시는 달력 규칙을 설명하는 가상 날짜이며 실제 공시 추출 정답이 아닙니다. 예를 들어 첫 행에서는 3월 30일은 허용하고 3월 29일은 허용하지 않습니다. 직접 입력은 0 이상의 정수 개월이며 0개월은 정확히 일치입니다. 소수·문자열·불리언·음수는 변환하지 않고 거절합니다. 실행일은 시간대가 있는 실행 시각을 한국 시간(Asia/Seoul)으로 바꾼 날짜입니다. API 요청 한도를 사용자 허용 개월의 상한으로 쓰지 않습니다. Python 날짜로 표현할 수 없는 허용 시작일은 계산 오류로 거절하고, 임의의 최대 개월 수나 시작일로 바꾸지 않습니다.

## 공시 검색 기간과 API 요청 범위

자료의 허용 기간은 표 안의 실제 자료 기준일을 제한합니다. 공시 검색 기간은 제출된 문서를 찾기 위한 별개 범위입니다. 최근 공시에 과거 수치가 들어갈 수 있으므로 두 범위를 같은 것으로 취급하지 않습니다. 과거 기준일 뒤에 제출됐더라도 실행일까지 공개된 관련 자료는 후보가 될 수 있습니다.

공시 검색 범위가 한 번의 API 요청 한도를 넘으면 해당 API의 공식 제한에 맞춰 기간을 나눠 조회합니다. 각 구간의 모든 페이지를 받고 접수번호 등 문서 식별자로 중복을 제거한 뒤 관련 원본·정정을 연결해야 합니다. 일부 구간이나 페이지가 실패하면 전체 검색을 완료했다고 표시하지 않습니다. 기간 분할이 제공되지 않는 오래된 자료를 복원해 주는 것은 아닙니다.

이는 합의한 수집 요구이며 분할 조회·페이지 통합 엔진은 아직 없습니다. API별 정확한 제한 수치·조회 가능 과거 범위는 구현할 때 공식 문서를 확인해 기록합니다. 이번 명세에서 일률적인 최대 개월 수를 만들지 않습니다.

## 시점 선택과 결과에 남길 것

재무 기준일은 공시 안의 표가 나타내는 날짜이고 공시일은 그 정보를 공개한 날짜입니다. 기준일 뒤에 공시된 보고서도 실행일까지 공개됐다면 사용할 수 있습니다. 요청 기준일 뒤의 재무 금액을 가져와 과거 기준일 금액으로 쓰지는 않습니다.

선택 대상은 요청한 재무 범위·항목과 맞는 자료입니다. 날짜가 맞아도 별도·연결이나 통화·항목이 다르면 대신 채우지 않습니다. 기준일 지정 모드는 해당 날짜 자료가 없을 때 허용 범위 안에서 가장 가까운 이전 기준일을 선택하고, 최신 모드는 실행일을 상한으로 가장 최근 실제 기준일을 선택합니다. 경과 범위를 지정하지 않았거나 정책이 모호하면 임의 한도로 실행하지 않습니다. 미래 자료·한도 밖 자료를 자동 대체하지 않습니다.

이전 자료를 선택하면 다음을 함께 보존하고 필요한 항목은 기본 결과에 표시합니다.

- 선택한 조회 모드·계산 기준 날짜와 실제 자료 기준일, 지정 모드의 사용자 요청 기준일
- 이전 자료 사용 여부와 선택 이유
- 선택한 허용 기간·계산된 허용 시작일
- 원문 금액·단위·통화·재무 범위와 근거 위치
- 사용한 공시 식별자·공시일·문서 버전과 정정 반영 여부
- 조회 실행 시각과 적용한 공시 마감

정정은 조회 대상 수치와 관련된 최신 유효 내용을 사용합니다. 제목에 정정이라는 말이 있다는 것만으로 다른 기간이나 다른 보고서를 덮어쓰지 않습니다. 원본과 정정본의 연결·해당 항목의 변경 범위·버전을 확인하는 구현이 필요하며, 아직 해당 엔진은 없습니다.

## 현금 계약 v1과의 관계

사용자 요청의 기준일과, 추출할 표의 선정된 기준일을 구분합니다. 예를 들어 사용자가 2025-12-31을 요청하고 허용 범위 안에서 2025-09-30 자료를 선정했다면, 추출에 전달하는 CashQuery.as_of는 실제 표의 2025-09-30입니다. 상위 실행 기록에는 원래 요청일 2025-12-31과 대체 사용 사실을 따로 남깁니다.

CashValue.as_of와 CashQuery.as_of는 여전히 같아야 합니다. 기존 다른 날짜 거절 테스트와 원문 정답은 유지합니다. 이는 실제 금액의 날짜를 바꿔 표시하지 못하게 하는 경계입니다. 새 날짜 선택 계약과 기존 추출 함수를 연결한 운영 엔진은 아직 없습니다. 추출 함수가 과거 자료를 자동 선택하도록 바뀐 것은 아닙니다.

기존 CASH-003은 이 날짜 혼동 금지로 적용합니다. 사용자가 허용한 이전 자료 선택을 명시적으로 기록하는 것과, 다른 시점을 요청 시점의 금액으로 위장하는 것은 구분합니다.

## 최종 파일과 내부 검증 기록

최종 엑셀은 연락할 법인을 추리는 결과물입니다. 기본 시트에는 조건 충족을 확인한 법인과 필요한 금액·사실·기준일·근거 링크를 담습니다. 이때 연락 우선순위 점수나 영업 제안을 자동 생성하는 정책을 추가한 것은 아닙니다.

확인 불가를 조건 미충족이나 0원으로 취급하지 않습니다. 기본 시트에서 제외하더라도 내부 기록에 법인·이유·확인 경로·실패·원문·남은 확인을 남깁니다. 사용자가 검토 내역 포함을 선택하면 이를 같은 파일의 별도 시트에 제공합니다. 옵션을 켜지 않아도 감사·재검증용 내부 기록을 지우지 않습니다. 조건을 충족하지 않은 정상 결과와 확인 불가를 내부 집계에서도 구분합니다.

실제 자료 기준일과 이전 자료 사용 여부는 대상 판단에 영향을 주므로 기본 결과에서도 숨기지 않습니다. 근거 링크와 정정 여부도 사용한 사실을 대조할 수 있게 표시합니다. 최종 열 순서·메모 배치·표시 정밀도는 아직 정하지 않았습니다.

## 아직 정할 것과 구현하지 않은 것

- 실행일 현재 상장법인 목록의 수집 출처·버전·완전성 확인, 중복 종목의 법인 통합 방식
- API별 제한 확인과 분할·페이지 수집 완전성 검증
- 최초 보고서와 정정의 연결 방법, 해당 항목이 변경되지 않은 정정·여러 동률 후보 처리
- 사건 기간의 경계와 보상·담보대출의 구체 조회 대상
- 유형별 자산 범위·환율·평가 기준·금액 비교·조건 판정
- 최종 엑셀 양식과 내부 기록의 저장 방식·보관 기간

평가용 수집기가 정정 전 원본을 보존하는 것은 회귀·대조 자료 수집 목적입니다. 이번 운영 결과 선택 정책과 구분하며, 그 수집기의 동작이나 기존 테스트 정답을 조용히 바꾸지 않습니다. 실제 수집·선택·판정·출력 구현은 계약과 사례를 준비한 뒤 연결합니다.

## Python 공통 계약 v1

이번 구현은 금액·보유 상태 조회의 **공통 부분**입니다. src/dartness/query_contract.py와 tests/test_query_contract.py가 담당합니다. 유형별 금액 조건·대상 자산·재무 범위의 입력은 아직 정의하지 않았으며 이 객체만으로 전체 조회를 실행할 수 없습니다. 사건 기간·주식보상·주식담보대출 요청을 금액 조회로 바꾸지 않습니다.

| 객체·함수 | 필드·역할 |
|---|---|
| SnapshotRequest | query_type=cash/try-assets/us-bonds, mode=latest/as_of, 필수 max_age_months, 선택 as_of, include_review=False, contract_version=snapshot-v1 |
| QueryRun | request, 필수 시간대 포함 executed_at, 계산된 execution_date·anchor_date·earliest_date. 모집단 날짜는 execution_date이며 공시 마감의 실행 시각도 보존 |
| SelectedDate | run, actual_date, status=selected, 자동 계산 is_prior. 실제 날짜는 허용 구간 안이어야 함 |
| DateNeedsReview | run, status=needs_review, reason=period_unavailable. 실제 날짜·금액 없음 |
| select_date(run, candidates) | 같은 법인·항목·범위·통화에 맞게 준비한 날짜 후보 중 허용 구간 내 최댓값을 반환. 없으면 DateNeedsReview |

모드·개월 수에는 기본값이 없습니다. latest에는 as_of를 넣지 않고, as_of 모드에는 날짜만 넣습니다(datetime·문자열은 거절). 지정 기준일이 한국 실행일보다 미래이면 아직 도래하지 않은 기준일이므로 거절합니다. include_review는 불리언만 허용합니다. executed_at을 생략하거나 시간대 없이 전달해 서버 시간대를 암묵적으로 쓰지 않습니다. 유효하지 않은 입력은 ValueError이며, 누락된 필수 생성자 인자는 Python의 TypeError입니다.

실행 기록과 결과는 불변 데이터 객체입니다. 실행 기록의 날짜는 입력에서 계산하며 외부에서 별도 지정할 수 없습니다. SelectedDate를 직접 만들더라도 한도 밖 날짜는 거절합니다. 선택 결과의 is_prior는 실제 자료 날짜가 anchor_date보다 이전인지를 뜻하며 최신 모드에서도 표시합니다. 최종 출력에는 모드·계산 기준 날짜·실제 자료 날짜를 함께 사용해야 합니다.

이 함수는 공시를 읽거나 문서·정정을 선택하지 않습니다. 날짜 중복은 같은 날짜로 처리하되 동일 날짜의 여러 문서 중 하나를 임의로 고르지 않습니다. 후보가 다른 법인·연결/별도·통화인지 확인하는 책임과 수집 완전성 확인은 상위 단계에 있으며 아직 연결하지 않았습니다. 날짜 선택 성공을 공시 사실·조건 충족으로 표시할 수 없습니다. 선택된 날짜만 기존 CashQuery.as_of에 전달할 수 있고 원래 요청과 실행 기록은 함께 보존해야 합니다.
