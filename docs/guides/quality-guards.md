# 예외 처리와 검사 우회 방지

상태: 2026-11-24 사용자 요청으로 기존 린트·테스트·CI를 보강합니다. AGENTS에 당부를 늘리는 대신 실행 가능한 검사를 연결합니다. 기존 요구사항·정답·위임 권한은 유지합니다.

## 린트로 막는 것

기존 Ruff 규칙에 BLE001(포괄 예외 잡기), S110(예외 후 pass), S112(예외 후 continue), PGH003(코드 없는 type-ignore), PGH004(코드 없는 noqa), RUF100(불필요한 noqa)을 추가합니다. 구체적인 예외 종류를 지정한 pass·continue도 검사하도록 check-typed-exception을 켭니다. 예외를 다시 던지거나 근거 있는 오류 처리까지 전부 금지하는 것은 아닙니다. 실제 실패가 정상 결과로 바뀌는지는 기존 실패 경로 테스트로 보완합니다.

기존 공시 예시 실행기는 기대한 예외 종류를 비교하기 위해 BLE001을 명시적으로 무시합니다. 불변성·잘못된 생성자 입력 테스트의 구체적인 type-ignore와 표 형식을 유지하는 fmt 무시도 기존 동작 그대로 둡니다. 이 보강을 이유로 정답이나 의미를 바꾸지 않습니다.

## PR에서 새로 생긴 우회 감지

PR base/head의 실제 Git 파일을 비교합니다. Python은 tokenize와 AST, JS/TS는 기존 Vite의 Oxc 파서를 사용합니다. 문자열·예시 데이터 안의 가짜 지시문은 검사 우회로 세지 않습니다. 파일 이동은 Git의 rename 연결로 이전 파일과 대조합니다.

감지 대상은 type-ignore·noqa·형식/타입/린트 무시 주석, 명시적 Any, pytest/unittest의 알려진 skip/xfail/importorskip 구문, Vitest의 skip/skipIf/runIf/only/todo/fails 구문입니다. 별칭 import와 재배치를 고려하고, 기존 구문의 수를 넘는 추가나 의미가 바뀐 구문이 있으면 PR 검사를 실패시킵니다. 기존 예외를 줄이거나 삭제하는 것은 허용합니다. 지시문이 붙은 코드 줄이나 비활성 테스트 내용을 바꾸면 새 구문으로 보고될 수 있으므로 필요를 검토합니다.

검사 설정·워크플로·검사기 자체의 변경은 CI 요약에 따로 표시합니다. 설정 변경이 무조건 완화라고 판단하지 않으며, 표시를 사용자 승인으로 간주하지 않습니다. 기존 정책대로 정답·검사 완화·예외 추가는 근거와 사용자 확인이 필요합니다. 새 예외가 필요하면 검사를 우회하거나 조건을 몰래 낮추지 말고 구체적인 필요와 영향부터 설명합니다. 현재 자동 승인·해제 스위치는 없습니다. 사용자와 허용할 최소 범위를 정하고 별도 예외 정책 변경을 검토하기 전에는 실패를 유지합니다.

## 실행과 보고

기존 code-quality에서 의존성 설치 뒤 PR의 base/head로 변경 검사를 실행합니다. 결과와 검사 설정 변경 목록을 Actions 로그와 실행 요약에 남깁니다. 읽기·구문 분석·Git 비교가 실패하면 정상으로 넘기지 않습니다. PR 밖에서는 기존 전체 린트·테스트를 계속 실행하며 이 PR 비교 단계를 실행하지 않습니다.

로컬에서는 `python -m scripts.check_quality_changes --base 기준커밋 --head 작업커밋`으로 비교합니다. Node.js와 기존 dashboard 의존성이 필요합니다. CI의 실제 명령과 자동 테스트는 구현 파일·PR에서 확인합니다.

## 한계

이 검사는 사람 승인 인증이나 보안 경계가 아닙니다. 에이전트가 검사기·워크플로와 코드를 함께 수정할 수 있는 권한 문제까지 해결하지 않습니다. 계산형 호출·동적으로 만든 별칭·기존 예외 재활용·검사 밖의 실행 환경 변경·모든 테스트 정답 변경을 완전하게 탐지하지 않습니다. 파일을 복잡하게 바꿔 Git이 rename을 찾지 못하면 새 파일로 취급해 추가 확인이 필요할 수 있습니다.

복잡도·중복·불필요한 추상화 전체를 자동 판정하거나 기존 테스트 삭제·assert 약화·정답 조작을 모두 보호하는 작업은 이번 범위가 아닙니다. 관측한 실패에 맞춰 규칙을 보강하며 통과 자체를 코드 품질 보증이라고 표현하지 않습니다.
