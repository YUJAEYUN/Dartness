# 상장법인·공시 연결의 실제 API 검증

상태: 2026-11-25 사용자 요청으로 실제 API 검증을 준비합니다. 일반 CI의 합성 테스트와 실제 운영 검증을 구분합니다.

## 실행 범위와 한도

기존 Check code 수동 실행에 listed_check_mode를 추가합니다. off는 기본값이며 DART를 호출하지 않습니다. probe는 최대 20회 한도에서 등록파일·앞의 세 법인 기업개황·전날 한국 날짜 하루의 공시 첫 페이지 형식을 확인합니다. 사전 점검 결과는 전체 모집단/전체 페이지 성공이 아닙니다.

probe에서 후보 법인 수와 공시 페이지 수를 확인한 후, 예상 요청이 한도 안에 있을 때 full을 최대 5,000회로 한 번 실행합니다. full은 실제 collect_listed_filings를 사용해 전체 후보 기업개황과 공시 모든 페이지를 연결합니다. 두 실행의 전체 상한은 사전 점검 20회와 full 5,000회입니다. 다른 작업의 API 사용량과 실제 남은 한도는 알 수 없으므로 실제 요청 제한 오류를 우회하지 않습니다. 자동 재시도·주기 실행·병렬 호출은 하지 않습니다.

검색 기간은 한국 실행일의 전날 하루로 고정합니다. 현재 날짜의 기업개황 모집단과 과거 제출일을 구분하는 운영 사례이며 사용자 조회 기간의 기본값을 바꾼 것이 아닙니다. 실행은 약 50분의 내부 시간 한도와 Actions 작업 60분 한도로 중단합니다. API 요청별 기존 30초 제한을 유지합니다.

## 시크릿과 결과

DART_API_KEY는 Actions 런타임 환경변수에서만 읽고 명령행·로그·보고서에 넣지 않습니다. 출력에는 상태·요청 시도/응답 수·후보/법인/공시 수·공식 출처 해시·관측 시각·최소 식별 정보·실패 코드와 필드 자료형을 남깁니다. 연락처·주소·대표자·상위 API 메시지는 저장하지 않습니다. 등록 ZIP은 공개 원천 대조용으로 보존할 수 있으며 키 포함 여부를 확인합니다. 아티팩트는 3일 보존하고 저장소 main에 실제 수집 결과를 커밋하지 않습니다.

진행 보고는 주기적으로 저장하고 실패 후에도 아티팩트 업로드를 시도합니다. probe_only·running·failed·complete_listing을 구분합니다. full 실패·한도·시간 초과·권한 오류는 성공으로 바꾸지 않습니다. 새 동작을 검증하기 위해 기존 정답이나 검사 기준을 출력에 맞춰 수정하지 않습니다.

## 완료 판단과 한계

probe는 소수 API 응답의 계약 적합성 확인이며 complete_listing이 아닙니다. full이 성공해도 OpenDART가 제공한 자료의 연결 관측입니다. 독립 KRX 명부 대조·원천 누락/갱신 지연 제거·자산/재무 금액·정정 적용·엑셀 정확성을 검증하지 않습니다. API 키·실행 권한·호출 예산 때문에 실행할 수 없다면 해당 조건을 미완료로 남기고 필요한 사용자 조치를 구체적으로 안내합니다.

실제 실행의 커밋·기간·요청 수·시장별 법인 수·공시 수·아티팩트·한계는 이슈와 PR에 기록합니다. 결과 기록 없이 코드와 워크플로만 추가한 것을 실제 검증 완료라고 표현하지 않습니다.
