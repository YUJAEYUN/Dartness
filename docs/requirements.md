# 합의한 요구사항

상태: 사용자와 논의한 요구사항. 세부 정책은 아래의 미결 사항을 따릅니다.

## 목적

- 비전공자가 템플릿으로 지정한 조건에 해당하는 법인을 조회합니다.
- 영업 제안·상품 추천·투자 평가는 수행하지 않습니다.
- 구조화 API에 없는 정보는 공시 원문·주석·첨부 등에서 확인합니다. 정기보고서만으로 대상을 제한하지 않습니다.
- 조회 조건·계산·출력은 코드가 통제하고, 에이전트는 문서 의미를 해석해 검증할 후보를 만듭니다.

<a id="accuracy"></a>
## 정확성과 근거

- 한 공시의 여러 열에서 요청한 시점·기간을 구분합니다. 잔액·분기 금액·누적 금액을 혼동하지 않습니다.
- 숫자와 함께 적용 단위·통화·기간·연결/별도를 확인합니다. 알 수 없으면 추정하지 않습니다.
- **AMOUNT-001:** 적용 단위를 확인할 수 없는 금액은 추정하지 않고 확인 필요로 처리합니다.
- 원문 값과 정규화한 값을 구분하고, 환산·합산은 코드로 처리합니다.
- 총액과 전체 세부내역의 범위를 확인한 후 합계를 대조합니다. 소계 중복을 피합니다.
- 불일치는 임의 보정하거나 기업 오류로 단정하지 않습니다. 추출 오류와 정정 여부 등을 먼저 확인합니다.
- 기간·통화·연결/별도·합산 범위가 같고 표시 단위로 설명 가능한 작은 차이는 기본 결과표에서 강조하지 않습니다. 원문 값·정확한 차이·처리 근거는 내부 기록에 보존합니다.
- 법인 전체에 같은 오차 금액·비율이나 반올림 방식을 적용하지 않습니다. 표시 단위로 설명되지 않거나 비교 기준이 불명확한 차이, 조회 조건의 충족 여부를 바꾸는 차이는 확인 필요로 남깁니다.
- 검사별로 수행 여부와 결과를 남깁니다. 근거 없는 신뢰도 점수를 부여하지 않습니다.
- 사용자에게 근거 링크를 제공하고 링크가 문서 전체인지 해당 절인지 구분합니다.

<a id="cash-scope"></a>
## 현금 조회 범위 — 2026-11-20 확정

- 기본은 법인 자체의 현금및현금성자산입니다. 별도 또는 개별 재무제표를 사용합니다.
- 자회사를 포함한 그룹 전체 금액은 연결 기준을 선택했을 때 조회합니다.
- **CASH-001:** 별도·개별 금액을 확인하지 못해도 연결 금액으로 대신 채우지 않습니다.
- **CASH-002:** 금액을 확인하지 못하면 0원으로 대신 채우지 않습니다. 확인 불가 결과에는 금액이 없습니다.
- API에서 못 찾으면 원문을 추가 확인합니다. API 조회 실패만으로 자료가 없다고 확정하지 않습니다.
- **CASH-003:** 요청한 시점의 금액을 찾지 못하면 다른 시점의 금액으로 대신 표시하지 않습니다.
- 해당 공시에 재무제표가 없음, 요청한 시점 자료가 없음, 표·단위 해석이 어려워 추출하지 못함을 구분해 기록합니다. 확인한 경로와 남은 확인 사항을 보존합니다.
- 결과에는 금액의 기준(별도·개별·연결), 시점, 단위와 근거 링크를 표시합니다.

세부 입력·출력과 검증 준비는 [현금 조회 계약 초안](cash-query-contract.md)을 따릅니다. 이 합의는 조회 기준이며 추출기가 구현됐다는 뜻은 아닙니다.

## 결과물

전문용어와 긴 설명을 최소화하고, 글자·금액·기준일·링크를 한눈에 읽을 수 있게 합니다. 의미가 달라지는 쉬운 표현으로 바꾸지 않습니다. 조회 종류가 달라도 기본 양식과 시각 규칙을 최대한 통일합니다.

## 아직 정하지 않은 것

기본 조회 시점, 반올림 허용 범위, 불일치 결과의 포함 정책, 최종 엑셀 열·메모 배치, 문서별 대체 경로, 캐시 저장 기술과 보관 기간은 미결입니다.
