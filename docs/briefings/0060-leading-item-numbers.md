# 계정명 앞의 목차 기호 읽기

## 한 줄 요약

현금 표 추출기가 "(5)현금및현금성자산"처럼 계정명 앞에 목차 기호가 붙은 행도 현금 행으로 읽습니다. 형식을 하나씩 나열하지 않고 "뜻을 바꾸지 않는 표시만 떼고 단어는 떼지 않는다"는 원칙을 계정명 정리 함수 하나로 만들었습니다. 대한약품 사례는 이제 개발용입니다.

## 지도에서의 위치

```mermaid
flowchart LR
    C[원문 수집] --> D[현금 행·열 추출]
    D --> E[단위 정규화]
    classDef changed fill:#dbeafe,stroke:#2563eb,stroke-width:3px
    classDef same fill:#f9fafb,stroke:#d1d5db
    class D changed
    class C,E same
```

D 단계의 상태는 "일부" 그대로입니다. 읽을 수 있는 계정명 형식이 하나 늘었습니다.

## 무엇이 달라졌나

| 계정명 | 전 | 후 |
|---|---|---|
| `(5)현금및현금성자산`, `5.`·`Ⅴ.`·`가.`·`(a)`·`①`·`(5)1.`이 앞에 붙은 경우 | 확인 필요 | 금액 |
| `제한된 현금및현금성자산`, `현금및현금성자산 등` (단어가 붙음) | 확인 필요 | 확인 필요 |
| `5현금및현금성자산` (괄호·마침표 없는 숫자) | 확인 필요 | 확인 필요 |
| `(주)현금및현금성자산`, `(주4)현금및현금성자산` | 확인 필요 | 확인 필요 |

- 계정명 정리는 새 함수 `core_account_name`(src/dartness/account_label.py)이 맡습니다. 현금 추출기는 정리된 이름이 `현금및현금성자산`과 같은지만 봅니다. 다른 조회 유형도 같은 함수에 자기 계정명을 비교하면 됩니다.
- 대한약품 2025 사업보고서는 이제 원문에서 43,972,786,132원을 읽습니다. 두 번째 평가의 나머지 8건 결과는 그대로입니다.

## 누가 무엇을 정했나

**사용자가 정한 것**
- 계정명 앞의 항목 번호를 허용합니다(2026-11-23, 이슈 #56).
- 형식을 하나씩 추가하지 않고, 맥락상 목차 기호는 모두 허용합니다. 확장성을 고려해 설계합니다(2026-11-23).

**구현 중 에이전트가 정한 것**
- 목차 기호의 범위: 숫자·로마 숫자·영문자 한 글자·한글 한 글자를 괄호로 감싸거나 마침표를 붙인 것, 원문자. 여러 개가 이어져도 뗍니다.
- 괄호·마침표 없는 숫자(`5현금…`)와 앞의 `(주)`·`(주4)`는 떼지 않습니다. 목차인지 확실하지 않기 때문입니다.
- 단어를 떼는 규칙은 넣지 않습니다. 뜻이 다른 계정을 현금으로 읽을 위험이 있습니다.
- 정리 함수는 현금 추출기 밖의 별도 모듈로 두었습니다. 다른 추출기가 생기기 전에 그 이상의 구조는 만들지 않았습니다.
- 대한약품 1건만 개발용으로 바꾸고 나머지 8건은 검증용으로 둡니다.

## 확인해 주세요

없음. 허용 범위는 사용자가 정한 원칙("맥락상 다 허용")을 따랐습니다. 떼지 않기로 한 예외(괄호 없는 숫자, 앞의 `(주)`)가 마음에 걸리면 알려 주세요.

## 확인한 것과 못 한 것

| 확인한 것 | 못 한 것 |
|---|---|
| 새 테스트가 고치기 전에는 실패하고 고친 뒤 통과함 | 새 형식을 처음 보는 다른 법인 원문으로 검증 |
| 정리 함수의 떼는 경우·떼지 않는 경우 테스트 | 실제 공시에서 목차 기호가 어떤 형식으로 얼마나 쓰이는지 |
| 기존 정답·개발용 사례 결과 그대로, 틀린 금액 0 | 변이 테스트 재실행 |
