# 계정명 앞의 항목 번호 읽기

## 한 줄 요약

현금 표 추출기가 "(5)현금및현금성자산"처럼 계정명 앞에 항목 번호가 붙은 행도 현금 행으로 읽습니다. 그래서 두 번째 평가의 대한약품 사례는 이제 개발용입니다.

## 지도에서의 위치

```mermaid
flowchart LR
    C[원문 수집] --> D[현금 행·열 추출]
    D --> E[단위 정규화]
    classDef changed fill:#dbeafe,stroke:#2563eb,stroke-width:3px
    classDef same fill:#f9fafb,stroke:#d1d5db
    class D changed
    class C,E same
```

D 단계의 상태는 "일부" 그대로입니다. 읽을 수 있는 계정명 형식이 하나 늘었습니다.

## 무엇이 달라졌나

| 계정명 | 전 | 후 |
|---|---|---|
| `(5)현금및현금성자산` | 확인 필요 | 금액 |
| `5.현금및현금성자산`, `Ⅴ. 현금및현금성자산` | 확인 필요 | 금액 |
| `(5)1.현금및현금성자산` (번호 두 개) | 확인 필요 | 확인 필요 |
| `가.현금및현금성자산`, `①현금및현금성자산` | 확인 필요 | 확인 필요 |
| `(주4)현금및현금성자산` | 확인 필요 | 확인 필요 |

대한약품 2025 사업보고서는 이제 원문에서 43,972,786,132원을 읽습니다. 두 번째 평가의 나머지 8건 결과는 그대로입니다.

## 누가 무엇을 정했나

**사용자가 정한 것**
- 계정명 앞의 항목 번호를 허용합니다(2026-11-23, 이슈 #56).

**구현 중 에이전트가 정한 것**
- 허용 형식을 괄호 안 숫자 `(5)`, 숫자와 마침표 `5.`, 로마 숫자와 마침표 `Ⅴ.`로 정했습니다. `(5)`는 대한약품 원문에서 봤고, `Ⅰ.`은 같은 표의 다른 행("Ⅰ.비유동자산")에서 봤습니다. `5.`는 실제 사례에서 보지 못했지만 같은 종류의 번호라 함께 넣었습니다.
- 번호는 하나만 허용합니다. `가.`, `①` 같은 기호는 허용하지 않습니다.
- 대한약품 1건만 개발용으로 바꾸고 나머지 8건은 검증용으로 둡니다. cases.json에 사례별 case_status를 추가했습니다.

## 확인해 주세요

1. **`5.` 형식을 함께 허용해도 될까요?** 실제 사례에서 본 형식은 아닙니다. 빼기를 원하시면 테스트와 정규식에서 지우겠습니다.

## 확인한 것과 못 한 것

| 확인한 것 | 못 한 것 |
|---|---|
| 새 테스트가 고치기 전에는 실패하고 고친 뒤 통과함 | 새 형식을 처음 보는 다른 법인 원문으로 검증 |
| 기존 정답·개발용 사례 결과 그대로, 틀린 금액 0 | `가.`, `①` 같은 다른 번호 형식이 실제로 얼마나 쓰이는지 |
| 대한약품 원문에서 정답 금액 추출 | 변이 테스트 재실행 |
