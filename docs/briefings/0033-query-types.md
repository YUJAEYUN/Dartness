# 올인원 조회 유형 명세

## 한 줄 요약

사용자가 실제로 요청한 다섯 가지 조회를 하나의 명세로 정리하고 대시보드 상단에 카드로 보여주게 됐습니다. 현금만 일부 구현됐고 나머지 네 가지는 명세 단계입니다.

## 지도에서의 위치

처리 흐름 단계의 상태는 바뀌지 않았습니다. 지금의 지도는 현금 조회 경로이며, 다른 유형의 지도는 아직 없습니다.

## 무엇이 달라졌나

| 조회 유형 | 상태 | 가장 큰 미결 질문 |
|---|---|---|
| 현금및현금성자산 금액 | 일부 | 기준일 기본값, 정정 공시 선택 |
| 터키 리라화(TRY) 자산 | 미구현 | 현금·예금만인지 전체 자산인지, 원화 환산 기준 |
| 미국채권 보유 금액 | 미구현 | 국채만인지 회사채도 포함인지, 평가 기준 |
| 주식보상과 위탁 증권사 | 미구현 | 제도 존재와 실제 부여·지급의 구분, 증권사의 역할 |
| 주식담보대출 관련 법인 | 미구현 | 법인 차입과 주요주주 개인 차입 중 무엇인지 |

모든 유형이 거칠 공통 흐름도 설계로 적었습니다: 유형 확인, 입력 검증, 수집, 근거 탐색, 판정, 출력. 이 흐름을 실행하는 코드는 없습니다.

## 누가 무엇을 정했나

**사용자가 정한 것**
- 조회할 다섯 가지 유형. 실제 요청 사례에서 왔습니다.

**구현 중 에이전트가 정한 것**
- 미결 기준은 기본값으로 채우지 않고 미결로 남깁니다.
- 공통 책임(수집, 원문 보존, 표 읽기, 실패 기록)과 유형별 책임(근거, 판정)을 나눴습니다.
- 다른 법인 현금 평가(이슈 #31)를 보류하는 순서로 적었습니다. PR에는 누가 보류를 정했는지 기록이 없습니다.

## 확인해 주세요

1. **미결 질문 중 무엇부터 정할까요?** 명세에 따르면 다음 작업은 한 유형의 미결 질문 하나를 정하는 것입니다.
2. **이슈 #31 보류가 의도한 것인가요?** 다른 법인으로 현금 추출을 평가하는 일은 결과 정확도를 확인할 유일한 경로입니다.

## 확인한 것과 못 한 것

| 확인한 것 | 못 한 것 |
|---|---|
| Python 125개, UI 27개 테스트와 린트·타입·빌드 통과 | 새 유형의 공시 추출 정확도 (추출기가 없음) |
| 브라우저에서 유형 카드 5개, 미결·미구현 표시 | 여러 조건을 조합한 조회의 설계 |
| 정의하지 않은 상태 값이 카드에 들어가면 실패 (검토 중 발견한 버그를 테스트로 재현하고 수정) | |
