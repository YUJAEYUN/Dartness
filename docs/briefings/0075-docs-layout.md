# 문서를 목적별 폴더로 정리

## 한 줄 요약

루트의 문서 18개를 명세·설계·실행 방법으로 나누고 화면·생성기·검사의 참조 경로를 함께 갱신했습니다.

## 지도에서의 위치

문서 탐색과 저장소 유지보수 작업입니다. DART 처리 단계의 구현 상태는 바뀌지 않습니다.

## 무엇이 달라졌나

| 위치 | 찾을 내용 |
|---|---|
| specs | 요구사항·조회 계약·금액 처리·출력 기준 |
| design | 아키텍처·화면·조사·개발 원칙·문서 운영·환경 제안 |
| guides | 수집 실행·테스트·CI·개발 절차·위임 범위 |
| 루트와 기존 폴더 | 시작·상태·작업 결과·위키·사례·평가·브리핑·양식 유지 |

새 폴더 이름이 승인 상태를 뜻하지는 않습니다. 제안·조사와 확정한 기준은 원문의 상태 표시로 구분합니다. Python·대시보드 코드 위치와 Vercel 프로젝트 설정은 그대로입니다.

## 누가 무엇을 정했나

**사용자가 정한 것**

- 기존 상위 구조를 유지하면서 docs부터 정리하고 대시보드·Python 세분화는 뒤로 나눕니다.
- 좋은 레퍼런스에서 필요한 원칙만 가져옵니다.

**구현 중 에이전트가 정한 것**

- specs·design·guides 세 묶음으로 18개 문서를 이동했습니다. 작은 문서마다 폴더를 만들지 않았습니다.
- 링크·MkDocs·위키·AGENTS·화면·생성기 입력·테스트의 경로를 함께 갱신했습니다.
- 명세 PR 검사에는 새 경로와 예전 경로의 삭제를 모두 남겨 필수 브리핑 검사를 유지했습니다.

## 확인해 주세요

추가 결정은 없습니다. 다음 대시보드 폴더 정리는 별도 이슈에서 기능별 이동 범위와 참조 방향을 정합니다. DART 기준·정답·위임 정책은 바꾸지 않았습니다.

## 확인한 것과 못 한 것

| 확인한 것 | 못 한 것 |
|---|---|
| 문서 strict 빌드·원본/생성 일치·기존 Python/UI 검사 | 문서 위치만으로 의미 정합성이나 가독성 보증 |
| 새 명세와 예전 삭제 경로도 브리핑 필수임을 검사 | 과거 외부에 공유한 모든 URL의 유지 |
| 문서 예시 입력·기대값과 DART 동작 유지(소스 설명의 문서 경로만 갱신) | 대시보드 기능별 폴더·Python 모듈 세분화 |

운영 화면의 새 문서 링크 확인은 이슈·PR에 기록합니다.
