# 공통 공시 목록을 기간·페이지별로 수집

## 한 줄 요약

공식 OpenDART에서 명시한 제출일 범위의 모든 페이지를 수집하고 출처를 보존하며 일부 실패를 완료로 표시하지 않습니다.

## 지도에서의 위치

```mermaid
flowchart LR
    A[조회 조건 입력] --> B[법인·공시 찾기]
    B --> C[원문 수집]
    classDef changed fill:#dbeafe,stroke:#2563eb,stroke-width:3px
    class B changed
```

B 법인·공시 찾기의 공시 목록 수집 부분입니다. 현재 상장법인 모집단과 보고서 의미·정정 선택은 아직 없어 단계 상태는 일부로 유지합니다.

## 무엇이 달라졌나

법인코드·시장·공시유형 필터를 유지하면서 월별 구간·100건 페이지를 순서대로 요청합니다. 원본·정정의 접수번호·공시명·제출일·원문 링크를 보존합니다. 페이지 수/총 건수/행 수·범위·중복·충돌·호출 예산을 검사하며 어느 페이지든 실패하면 부분 목록을 성공 결과로 반환하지 않습니다. 날짜는 제출일이며 실제 재무 기준일이 아닙니다.

## 누가 무엇을 정했나

**사용자가 정한 것**

- 다섯 조회 유형이 공통으로 사용하는 기간 분할·페이지 수집·출처·실패 처리를 먼저 구현합니다.
- #32는 명세 작업 완료로 종료하고 #57은 필요할 때 재검토하는 보류로 남깁니다.

**구현 중 에이전트가 정한 것**

- 공식 3개월 제한 안에 있도록 비중첩 월 단위로 분할했습니다. 3개월씩 최적화하는 것보다 경계 검증을 우선해 요청 수가 더 많을 수 있습니다.
- 호출자는 요청 예산과 기존 fetch_bytes를 연결한 호출 함수를 명시합니다. 새 의존성·자동 재시도·병렬 요청·키 저장은 추가하지 않았습니다.
- 중복 제거 후 총 건수가 모자라면 누락 가능성으로 실패시킵니다. 정정 관계를 보고서명으로 추정하지 않았습니다.

## 확인해 주세요

추가 결정은 없습니다. 실행일 현재 상장법인 모집단 구성과 수집한 목록에서 재무 기준일·정정 후보를 만드는 부분은 후속으로 분리합니다.

## 확인한 것과 못 한 것

| 확인한 것 | 못 한 것 |
|---|---|
| 합성 응답으로 윤년·월말·모든 페이지·필터·날짜 상한·출처 보존 | 새 수집기로 실제 API를 호출하거나 전수 자료를 대조 |
| 오류·부분 실패·메타데이터 변화·중복/충돌·예산 중단 | 검색 중 같은 총 건수로 내용이 바뀌는 경우의 완전성 보증 |
| 기존 평가용 수집기·정답·조회 정책 유지 | 모집단·정정 선택·원문 추출·조건 판정·엑셀 |

공식 문서의 응답 계약을 검증한 코드이며 수집 성공이 자산 보유나 추출 정확성을 뜻하지 않습니다. 최종 CI·운영 근거는 이슈·PR에 남깁니다.
