# 기업개황 수집 속도를 소수 요청으로 비교

## 한 줄 요약

현재 명부의 정확성 기준을 유지하면서 공개 두 법인의 순차·동시 요청 시간을 비교합니다.

## 지도에서의 위치

전체 조회의 첫 단계인 현재 상장 명부 수집(A)의 성능 조사입니다. 현금 추출과 출력은 바꾸지 않습니다.

```mermaid
flowchart LR
    A[현재 상장 명부 수집] --> B[원문 수집]
    B --> F[현금 조건 조회]
    F --> I[엑셀 출력]
    classDef changed fill:#dbeafe,stroke:#2563eb,stroke-width:3px
    class A changed
```

## 무엇이 달라졌나

공식 호출 한도와 고유번호 변경 반영 시점을 정리하고 수동 profile_speed_probe 모드를 추가합니다. 두 법인에 순차 2회·동시 2회를 두 번 비교합니다. 최대 8회·동시 2개·시작 간격 0.5초이며 오류 뒤 새 요청과 자동 재시도는 없습니다. 실패 직전까지의 기록도 기존 데이터 브랜치에 보존합니다.

## 누가 무엇을 정했나

사용자는 속도 개선과 호출 한도 확인을 요청했습니다. 일일 한도를 처리 속도로 해석하지 않으며 개별 키의 설정을 추정하지 않습니다. 운영 명부의 당일 기업개황 확인·기존 5천 회 예산·권한·의존성·기존 정답은 유지합니다.

## 확인해 주세요

현재 사용자 판단이 필요한 변경은 없습니다. 이 작은 비교만으로 전수 수집의 속도와 안정성을 확정하지 않습니다. 전수 실행 예산과 운영 병렬화는 후속 판단입니다.

## 확인한 것과 못 한 것

고정 응답으로 호출 상한·간격·오류 중단·동시 요청 종료·법인 일치·개인 연락 정보 미보관을 검사했습니다. 실제 8회가 모두 성공했고 순차 두 건 2.199/2.023초, 동시 두 건 1.248/1.265초였습니다. 응답의 법인·종목코드와 해시가 일치했습니다. 이 소수 표본으로 전수 시간이나 오류율을 예측하지 않습니다. 일반 CI는 실제 DART를 호출하지 않습니다. 현재 키의 개별 일일 한도·남은 호출 수·독립 전수 E2E는 확인하지 않았습니다.
