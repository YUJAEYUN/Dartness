# 상장법인 연결을 실제 API로 확인하기

## 한 줄 요약

정해둔 호출 한도 안에서 실제 OpenDART 연결을 확인하는 수동 검사를 추가했습니다. 사전 점검은 5회 호출로 성공했고 보고서의 예상 4,029회가 한도 안이어서 전체 실행을 시작했습니다. 결과는 아직 확인 전입니다.

## 지도에서의 위치

```mermaid
flowchart LR
    A[조회 조건 입력] --> B[법인·공시 찾기]
    B --> C[원문 수집]
    classDef changed fill:#dbeafe,stroke:#2563eb,stroke-width:3px
    class B changed
```

B 단계의 실제 연결을 확인하는 작업입니다. 전체 검증이 끝나지 않아 일부 상태를 유지합니다.

## 무엇이 달라졌나

일반 PR에서는 실제 API를 호출하지 않습니다. 수동 실행에서 사전 점검과 전체 연결을 구분하고 요청 수·원천 해시·실패 단계·진행 기록을 보존합니다. 중간 실패나 한도 초과를 성공으로 표시하지 않습니다.

## 누가 무엇을 정했나

**사용자가 정한 것**

- 기존 시크릿으로 실제 DART 연결 검증을 이어갑니다.

**구현 중 에이전트가 정한 것**

- 사전 점검 최대 20회 후 예상 규모를 확인하고 전체 최대 5,000회를 한 번 실행합니다. 자동 재시도는 없습니다.
- 전날 한국 날짜 하루를 운영 사례로 사용합니다. 사용자 조회 기간의 기본값을 바꾸지 않습니다.
- 내부 약 50분·Actions 60분 한도를 두고 결과 파일은 3일 보관합니다. 기업개황의 개인정보와 키는 출력하지 않습니다.

## 확인해 주세요

추가 결정은 없습니다. 사용자가 제공한 사전 점검 보고서를 확인하고 전체 실행을 시작했습니다. 전체 결과 확인과 병합은 아직 완료하지 않았습니다.

## 확인한 것과 못 한 것

| 확인한 것 | 못 한 것 |
|---|---|
| 실제 사전 점검의 probe_only·요청 5회·Actions 성공 | 등록 ZIP 자체의 해시 재대조 |
| 합성 응답의 예산·시간·실패·소수 점검/전체 성공 구분 | 실제 전체 상장법인·공시 연결의 완료 결과 |
| 일반 PR의 실제 호출 방지와 기존 정답 유지 | 독립 거래소 명부·재무금액·정정·엑셀 정확성 |
