# 현금 표 추출 첫 평가

## 한 줄 요약

개발에 쓰지 않은 6개 법인의 DART 2025 사업보고서로 현금 표 추출기를 처음 평가했습니다. 틀린 금액은 한 번도 없었지만, DART 원문을 그대로 넣으면 11건 중 하나도 읽지 못했습니다.

## 지도에서의 위치

```mermaid
flowchart LR
    C[원문 수집] --> D[현금 행·열 추출]
    D --> E[단위 정규화]
    classDef changed fill:#dbeafe,stroke:#2563eb,stroke-width:3px
    classDef same fill:#f9fafb,stroke:#d1d5db
    class D changed
    class C,E same
```

D 단계의 상태는 "일부" 그대로입니다. 바뀐 것은 이 단계가 무엇을 못 하는지에 대한 근거입니다. 원문 수집(C)이 받는 DART XML을 추출(D)이 읽지 못한다는 사실이 드러났습니다.

## 무엇이 달라졌나

| 조건 | 맞음 | 확인 필요 | 틀림 |
|---|---|---|---|
| DART 원문 그대로 | 0 | 11 | 0 |
| 셀 태그만 바꾼 변형 입력 | 7 | 4 | 0 |

- **원문을 못 읽은 이유:** DART 원문은 표 셀을 TE 태그로 씁니다. 추출기는 KIND HTML의 TD 태그만 읽습니다.
- **태그를 바꿔도 4건이 빠진 이유:** 삼성전자·셀트리온이 계정명을 "현금및현금성자산 (주4,29)"처럼 씁니다.
- **맞은 7건:** 원·백만원 단위가 섞이고 3개 기간 열이 있어도 정확했습니다.

## 누가 무엇을 정했나

**사용자가 정한 것**
- 6개 법인으로 평가하고, 결과가 나오면 바로 평가까지 진행합니다(2026-11-23).

**구현 중 에이전트가 정한 것**
- 입력 구간은 원문 "재무상태표" 제목 아래 첫 두 표를 그대로 자릅니다. 사람이 구간을 고르는 방식을 흉내 냈습니다.
- 정답은 원문에서 먼저 읽고 OpenDART API로 대조합니다. 11건 모두 같았습니다.
- 셀 태그만 바꾼 변형 조건을 함께 돌려, 형식 문제와 다른 문제를 나눠 봤습니다.
- 회귀 테스트는 "틀린 금액을 내지 않는다"만 고정합니다. 맞은 개수는 고정하지 않았습니다.
- 리노공업은 연결 재무제표가 없어 개별(individual)로 넣었습니다.

## 확인해 주세요

1. **추출기를 고칠까요?** 원문의 TE 태그 셀을 읽게 하고, 계정명 뒤의 주석 번호를 무시하게 하면 이번 11건은 모두 읽을 수 있을 것으로 보입니다. 다만 고치면 이 11건은 개발용이 되어, 정확도를 다시 확인할 새 법인이 필요합니다.

## 확인한 것과 못 한 것

| 확인한 것 | 못 한 것 |
|---|---|
| 11건의 정답을 원문에서 읽고 OpenDART API 값과 대조 | 사람의 독립 검토 |
| 두 조건 모두에서 틀린 금액 0건 | 분기보고서, 정정 공시, 다른 결산월, 금융업 서식 |
| 원문 위치·해시를 평가 자료에 기록 | 보고서 전체에서 구간을 자동으로 찾기 |
