# 조회 시점과 허용 개월 선택지

## 한 줄 요약

최신 자료/기준일 지정 모드와 정확히 일치·3/6/12개월·직접 입력을 기준 문서와 대시보드에 반영했습니다. 실제 조회·기간 계산 엔진은 아직 없습니다.

## 지도에서의 위치

입력(A)과 공시 수집(B, C)에 필요한 명세를 보완했습니다. 구현 단계 상태는 바뀌지 않았습니다.

## 무엇이 달라졌나

| 전 | 후 |
|---|---|
| 사용자가 기준일과 경과 기간을 직접 지정 | 최신 자료 또는 지정일, 허용 기간 선택지 제공 |
| 기간 단위·월말·경계 계산 미결 | 달력 개월을 한 번에 차감, 없는 날짜는 월말, 양끝 포함 |
| API 검색 기간과 자료 나이의 관계 불명확 | 문서 검색은 API 제한에 따라 분할하고 실제 수치 날짜는 별도 확인 |

예를 들어 2026-08-31 기준 6개월 허용은 2026-02-28부터 2026-08-31까지입니다. 실제 공시 추출 정답이 아닌 달력 설명 예시입니다.

## 누가 무엇을 정했나

**사용자가 정한 것**

- 최신 자료/기준일 지정과 정확히 일치·3/6/12개월·직접 입력을 사용합니다.
- 개월은 달력 기준이며 없는 날짜는 월말로 보정하고 시작일도 포함합니다.
- 최신 모드는 실행일, 지정 모드는 지정일로 허용 기간을 계산합니다. 실제 자료 날짜를 표시합니다.
- 긴 공시 검색 범위는 시스템이 나눠 조회·통합합니다.

**구현 중 에이전트가 정한 것**

- 기존 정책 표를 갱신해 대시보드에 같은 기준이 생성되도록 했습니다. 별도 화면 입력 기능은 만들지 않았습니다.
- 평년·윤년·정확히 일치 예시와 API 제한 수치 확인이 필요한 범위를 명시했습니다. API별 최대 개월은 임의로 만들지 않았습니다.

## 확인해 주세요

이번 합의를 반영하기 위해 추가로 판단할 것은 없습니다. 직접 입력의 유효 범위와 실행일 시간대는 실행 계약에서 정할 미결로 남겼습니다.

## 확인한 것과 못 한 것

| 확인한 것 | 못 한 것 |
|---|---|
| 정책 표와 생성 화면 데이터의 일치, 문서 링크·형식 | 실제 최신 자료 선정·달력 계산·API 기간 분할 |
| 기존 코드와 공시 정답·검사 기준 유지 | API별 정확한 조회 한도·과거 제공 범위 |
| 기존 Python·화면 검사 통과 | 전체 공시 정확도와 엑셀 생성 |

검사 통과는 명세의 실행 구현이나 의미 정합성을 자동 증명하지 않습니다. 검사·배포 근거는 이슈·PR에 남깁니다.
