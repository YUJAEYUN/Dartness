# 같은 날 원천을 재사용하고 중단된 수집 이어가기

## 한 줄 요약

소수 E2E에서 받은 원천을 매번 버리지 않고 같은 날짜 안에서 검증해 다시 사용합니다.

## 지도에서의 위치

```mermaid
flowchart LR
    B[원천·관측 시각·파일 해시] --> F[새 기업개황·이력·본문으로 검증]
    F --> B
    classDef changed fill:#dbeafe,stroke:#2563eb,stroke-width:3px
    class B,F changed
```

## 무엇이 달라졌나

법인 코드 ZIP과 같은 접수번호 원문만 한국 시각 같은 날짜·파라미터·해시·크기를 확인해 재사용합니다. 기업개황·목록·본문·표는 매번 새로 받습니다. 응답별 체크포인트를 남기고 최종 결과가 없는 중단 실행도 명시한 후속 실행에서 원천을 재사용할 수 있습니다.

## 누가 무엇을 정했나

사용자가 속도 보강을 승인했습니다. 적용은 기존 수동 소수 E2E에 한정하고 전수 명부·조회/판정 기준·기존 정답을 바꾸지 않습니다. 기존 의존성·권한을 유지합니다.

## 확인해 주세요

추가 결정 요청은 없습니다. 오래된 날짜·잘못된 파일/해시·미완료 원천은 사용하지 않고 새 수집으로 진행합니다. 무기한 캐시나 장중 변경이 절대 없다는 보장은 하지 않습니다. 다른 날짜와 실제 전수 모집단으로의 확대는 남아 있습니다.

## 확인한 것과 못 한 것

같은 날짜 원천 재사용·다른 날짜/미래/경로 이탈/변조/충돌/부분 기록 거절과 새 기업개황 적용을 검사합니다. GitHub 표본 실행에는 전체 360초 제한을 두고 종료/실패 뒤에도 저장된 안전한 부분 원천을 데이터 브랜치에 보존합니다. 실패가 성공으로 바뀌지는 않습니다. 실제 성공 실행에서 수집·조회 262.00→10.56초, 워크플로 전체 4분35초→23초를 관측했고 두 금액·원문/링크·엑셀 셀이 일치했습니다. 중간의 기업개황 시간 초과 실행도 두 법인 확인 필요로 보존합니다. 일반 속도 보장이나 전수 검증은 아닙니다. 상세 근거는 평가 기록과 이슈에 연결합니다.
