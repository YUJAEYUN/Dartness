# docs에서 대시보드 상태 만들기

## 한 줄 요약

대시보드 첫 화면이 docs/system-status.md를 읽어 처리 흐름 지도, 단계별 상태, 미결 질문, 다음 작업을 보여주게 됐습니다. 화면 문구를 따로 고치지 않아도 docs를 고치면 화면이 따라옵니다.

## 지도에서의 위치

처리 흐름 단계의 상태는 바뀌지 않았습니다. 조회 기능이 아니라 상태를 보여주는 화면 작업입니다.

## 무엇이 달라졌나

| 전 | 후 |
|---|---|
| 대시보드는 GitHub 이슈·PR·CI 목록만 표시 | 첫 화면에 처리 흐름 지도와 단계별 상태·근거, 미결 질문, 지금·다음·나중 표시 |
| 현금 결정 카드를 화면 코드에 직접 적어 둠 | 직접 적은 카드를 지우고 docs에서 생성 |
| docs와 화면이 달라져도 알 수 없음 | docs와 생성된 화면 자료가 다르면 필수 CI 실패 |

단계를 누르면 그 단계의 남은 범위와 근거가 나옵니다.

## 누가 무엇을 정했나

**사용자가 정한 것**
- 상태의 원본은 docs에 둡니다(PR #27에서 선택).
- 대시보드에서 흐름도를 직접 보고 싶다고 요청했습니다. 그래서 Mermaid 패키지를 추가했습니다.

**구현 중 에이전트가 정한 것**
- 생성된 화면 자료(dashboard/src/generated/system-status.json)를 저장소에 커밋하고, CI가 원본과 비교합니다.
- "구현" 단계에는 코드와 테스트 근거가 둘 다 있어야 합니다. 없으면 CI가 실패합니다.
- 화면에 원본 문서의 해시를 표시하고, 링크를 배포한 커밋에 고정합니다.
- 로컬 pre-commit 훅을 만들었습니다. 체크아웃마다 따로 설치해야 합니다.

## 확인해 주세요

없음. docs를 원본으로 두고 대시보드에서 관리하며 CI로 연결을 검사하는 방향은 이미 합의했습니다. 생성·커밋·검사는 [위임 정책](../guides/delegation.md)에 따라 작업 중인 에이전트가 수행하며, 사람이 매번 생성 명령을 실행하도록 요구한 것이 아닙니다.

생성 파일 커밋·근거 파일 검사·로컬 훅은 그 방향을 구현한 방식입니다. 실제 사용에서 문제가 생기면 검증 근거와 함께 개선하며 이미 합의한 방향을 반복해서 묻지 않습니다.

## 확인한 것과 못 한 것

| 확인한 것 | 못 한 것 |
|---|---|
| Python 125개, UI 22개 테스트와 린트·타입·빌드 통과 | 상태 판단 자체가 맞는지 |
| 브라우저(headless Chromium)에서 지도, 단계 9개, 미결 6개 표시 | 모바일 화면 (사용자와 합의해 보류) |
| 원본과 생성물이 다르면 CI 실패 | 훅을 설치하지 않은 환경의 로컬 확인 |
