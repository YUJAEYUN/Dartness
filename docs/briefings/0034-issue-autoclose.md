# 이슈가 먼저 닫히지 않게 막기

## 한 줄 요약

PR이 병합될 때 이슈가 자동으로 닫히지 않도록, PR 본문의 자동 종료 문구를 CI가 거절하게 됐습니다. 이제 이슈는 체크리스트를 확인한 뒤 따로 닫습니다.

## 지도에서의 위치

처리 흐름 단계의 상태는 바뀌지 않았습니다. 작업 절차를 바꾼 작업입니다.

## 무엇이 달라졌나

| 전 | 후 |
|---|---|
| PR 본문에 `Closes #32`를 쓰면 병합 때 이슈가 닫힘 | 그런 문구가 있으면 code-quality 실패. 이슈는 `Refs #32`로 연결 |
| 이슈 #32가 체크리스트가 남은 채로 닫힘 | 이슈를 다시 열고, 완료 조건을 확인한 뒤 따로 닫기로 함 |

PR 본문만 고쳐도 검사가 다시 돕니다. PR 템플릿, [위임 정책](../delegation.md), [CI 설명](../ci.md)에도 같은 규칙을 적었습니다.

## 누가 무엇을 정했나

**사용자가 정한 것**
- 이슈 #32가 일찍 닫힌 것을 지적했고, 열어 두라고 했습니다. #32는 지금도 열려 있습니다.

**구현 중 에이전트가 정한 것**
- 문서 규칙이 아니라 CI 검사로 막습니다(scripts/check_pr_policy.py).
- `Closes`, `Fixes`, `Resolves`의 여러 형태와 다른 저장소·URL 형식까지 거절합니다.

## 확인해 주세요

1. **이슈를 사람이나 에이전트가 직접 닫아야 합니다.** 닫는 걸 잊으면 끝난 작업이 열린 채 남습니다. 대시보드의 열린 작업 목록이 부정확해질 수 있는데, 괜찮은지 봐주세요.
