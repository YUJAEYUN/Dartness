# 이슈가 먼저 닫히지 않게 막기

## 한 줄 요약

PR이 병합될 때 이슈가 자동으로 닫히지 않도록, PR 본문의 자동 종료 문구를 CI가 거절하게 됐습니다. 이제 이슈는 완료 근거와 체크리스트를 먼저 확인·갱신한 뒤 따로 닫습니다.

## 지도에서의 위치

처리 흐름 단계의 상태는 바뀌지 않았습니다. 작업 절차를 바꾼 작업입니다.

## 무엇이 달라졌나

| 전 | 후 |
|---|---|
| PR 본문에 `Closes #32`를 쓰면 병합 때 이슈가 닫힘 | 그런 문구가 있으면 code-quality 실패. 이슈는 `Refs #32`로 연결 |
| 이슈 #32가 체크리스트가 남은 채로 닫힘 | 이슈를 다시 열고, 완료 조건을 확인한 뒤 따로 닫기로 함 |

PR 본문만 고쳐도 검사가 다시 돕니다. PR 템플릿, [위임 정책](../delegation.md), [CI 설명](../ci.md)에도 같은 규칙을 적었습니다.

## 누가 무엇을 정했나

**사용자가 정한 것**
- 완료 조건이 확인되지 않은 채 이슈 #32가 닫힌 것을 지적했습니다. 사용자가 모든 이슈를 직접 닫거나 매번 종료를 승인하겠다고 정한 것은 아닙니다.

**구현 중 에이전트가 정한 것**
- 지적을 받은 뒤 #32를 다시 열고 완료 근거를 기록했으며, 이번 이슈는 닫지 않고 남겨 두겠다고 알렸습니다. 당시 조치이며 현재 상태는 [이슈 #32](https://github.com/YUJAEYUN/Dartness/issues/32)에서 확인합니다.
- 문서 규칙이 아니라 CI 검사로 막습니다(scripts/check_pr_policy.py).
- `Closes`, `Fixes`, `Resolves`의 여러 형태와 다른 저장소·URL 형식까지 거절합니다.

## 확인해 주세요

없음. 완료 조건을 확인하기 전에 자동 종료하지 않도록 정리한 절차를 다시 승인받지 않습니다. 열린 작업과 보류 상태를 정확하게 기록하는 것은 에이전트의 작업 관리 책임입니다.

[위임 정책](../delegation.md)의 범위에서는 에이전트도 완료 근거를 확인하고 체크리스트를 먼저 갱신한 뒤 종료할 수 있습니다. 이번 #32를 열어 두기로 한 조치를 모든 이슈에 사람의 종료 승인이 필요하다는 규칙으로 확대하지 않습니다.
