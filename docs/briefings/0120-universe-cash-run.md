# 전체 상장 명부에서 제한한 법인의 현금 조회 연결

## 한 줄 요약

전체 명부를 유지하면서 명시한 일부 법인의 원문 수집·기존 최신 조회·통합 엑셀을 연결합니다.

## 지도에서의 위치

```mermaid

    A[현재 전체 상장 명부 확인] --> B[한도 내 원문·본문 수집]
    B --> F[기존 최신 선택·조건 비교]
    F --> I[전체 상태·통합 엑셀]
    classDef changed fill:#dbeafe,stroke:#2563eb,stroke-width:3px

```

## 무엇이 달라졌나

기존 collect_universe와 현금 일괄 조회를 실제 Fetch 콜백 경로로 연결한 개발자 API를 추가합니다. 명부 작성과 원문 수집이 하나의 API 예산을 사용하고 웹 예산은 따로 셉니다. 선택하지 않은 전체 대상은 한도 미처리로 보존하며 금액을 추정하지 않습니다. 시범값에 고정하지 않고 정확한 원화 금액을 입력받습니다.

## 누가 무엇을 정했나

사용자는 M1의 연결 이슈를 만들고 제한 실행부터 진행하기로 했습니다. 기존 모집단/조회/별도·개별·연결/출력 기준·정답·의존성·권한은 유지합니다. 확인된 재무 범위가 없으면 자동 분류하지 않습니다. 원문 상한을 넘으면 일부 보고서만 골라 사용하지 않습니다.

## 확인해 주세요

실제 전체 상장 명부를 새로 만드는 데 이전에는 약 4천 회·40분이 걸렸습니다. 원문 두 법인만 처리해도 이 비용은 남습니다. 현재는 합성 명부로 연결을 검사하며 실제 새 명부와 원문까지 실행할 API/시간 예산을 확인해야 합니다. 이번 첫 PR만으로 이슈 #121이나 M1을 닫지 않습니다.

## 확인한 것과 못 한 것

합성 세 시장 명부에서 일부만 수집해도 전체 상태가 보존되는지, 명부/원문 예산 부족·미확인 범위·잘못된 법인·금액 조건을 검사합니다. 현재 단계는 네트워크 콜백을 연결한 개발자 API이며 실제 새 명부/전수 현금/독립 E2E 성공을 의미하지 않습니다. 별도/개별 자동 확인과 정정 쌍 추가 증거 수집도 후속 범위입니다.
