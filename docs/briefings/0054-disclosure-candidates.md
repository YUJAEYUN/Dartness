# 공시 후보의 범위와 근거 보존

## 한 줄 요약

준비된 후보가 요청한 법인·항목·범위·통화와 맞는지 검사하고, 날짜를 고른 뒤에도 원문 출처를 보존합니다. 같은 날짜의 서로 다른 후보는 임의로 확정하지 않습니다.

## 지도에서의 위치

```mermaid
flowchart LR
    A[조회 조건 입력과 후보 검증] --> B[법인·공시 찾기]
    B --> C[원문 수집]
    classDef changed fill:#dbeafe,stroke:#2563eb,stroke-width:3px
    classDef same fill:#f9fafb,stroke:#d1d5db
    class A changed
    class B,C same
```

A의 지원 범위가 늘었으며 상태는 일부 그대로입니다. 실제 원문에서 후보를 만드는 기능이나 수집·현금 추출과 연결한 실행 흐름은 아직 없습니다.

## 무엇이 달라졌나

| 전 | 후 |
|---|---|
| 날짜만 받아 선택 | 법인·유형·항목·범위·통화의 일치도 검사 |
| 선택 날짜와 문서 근거가 따로 있음 | 요청·실제 날짜·공시일·문서 ID·해시·링크·위치·문맥을 함께 보존 |
| 같은 날짜의 여러 문서를 구분하지 못함 | 완전 동일 반복만 중복 취급하고 서로 다른 후보는 확인 필요로 보류 |

2026-09-30 요청에 6개월을 허용하고 6월 30일 후보 하나를 받으면 원래 요청과 해당 후보의 출처를 그대로 반환합니다. 9월 30일의 원본·정정 후보가 함께 있다면 최신 공시일만 보고 고르지 않습니다. 내부 결과에는 입력 후보 전체를 남깁니다.

## 누가 무엇을 정했나

**사용자가 정한 것**

- 후보 범위 검증과 날짜 선택 뒤 근거 보존 작업을 진행합니다.
- 같은 날짜에 여러 후보가 있으면 임의로 확정하지 않습니다.
- 클로드와 이슈 단위로 작업을 나눕니다. Codex는 #52, 수집·현금 평가 작업은 #31 범위와 분리합니다.

**구현 중 에이전트가 정한 것**

- 준비된 후보의 범위가 하나라도 다르면 전체 입력을 거절합니다.
- 완전히 동일한 후보 반복만 단일 후보로 취급하며 원래 목록은 보존합니다.
- 후보·상태·사유는 불변 입력에서 계산하고 외부에서 성공 상태를 지정하지 못하게 했습니다.
- 공시 마감은 공개 날짜로 검사합니다. 당일 정확한 공개 시각과 실제 URL·문서 ID·해시의 대응은 온라인 검증하지 않습니다.

## 확인해 주세요

이번 작업을 마무리하기 위해 추가로 판단할 것은 없습니다. 원문 후보 생성·유형별 조건·정정 연결은 후속 설계이며 이번에 기본값으로 채우지 않았습니다.

## 확인한 것과 못 한 것

| 확인한 것 | 못 한 것 |
|---|---|
| 신규 합성 검사 48개: 범위 혼합 거절·동일 날짜 보류·공시 마감·근거 보존 | 실제 공시에서 후보를 생성하고 항목 의미를 판정하는 기능 |
| Python 전체 340개·대시보드 40개, 타입·린트·문서·생성 일치·빌드 | 정정 연결·수집 완전성·금액 조건·엑셀 |
| 기존 날짜·현금 계약·수집기·추출기·fixture/정답 유지 | 상대 에이전트의 실시간 로컬 상태나 파일 잠금 |

선택 성공은 입력한 메타데이터가 맞는 한 건이라는 뜻입니다. 원문 사실이나 조건 충족을 확인한 결과가 아닙니다. 실제 API·LLM 호출 없이 검사했으며 병합·배포 근거는 이슈·PR에 남깁니다.
