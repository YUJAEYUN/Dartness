# 관리 화면에서 최신 GitHub 상태 확인

## 한 줄 요약

이슈를 닫아도 배포 저장본에는 열림으로 남던 문제를 수정했습니다. 화면 열기·다시 확인에서 최신 GitHub 상태를 조회하고, 실패하면 이전 자료와 그 시각을 명확히 표시합니다.

## 지도에서의 위치

관리 화면과 문서의 상태 설명을 고친 작업입니다. DART 처리 단계의 구현 상태·조회 기준은 바뀌지 않았습니다.

## 무엇이 달라졌나

| 전 | 후 |
|---|---|
| 다시 읽기도 배포 저장본만 읽음 | 공개 GitHub 상태를 새로 조회 |
| 배포 후 이슈 종료가 화면에 남음 | 다음 화면 조회에 반영, 새 배포 불필요 |
| 실패 시 자료 출처 혼동 가능 | 첫 실패는 저장본, 재조회 실패는 직전 자료 유지·경고 |
| 개발 원칙에 오래된 미구현 설명이 남음 | 현재 범위는 시스템 상태·기준 문서로 연결 |

조회 시각 이후의 변경은 자동 추적하지 않습니다. docs·브리핑은 배포 커밋에 고정하고 GitHub 조회 시각과 구분합니다.

## 누가 무엇을 정했나

**사용자가 정한 것**

- 상태 설명 정리와 대시보드 최신 상태 조회를 먼저 개선합니다.
- 기존 구조와 검사를 재사용하고 새 하네스 전체를 만들지 않습니다.
- 개발 결과 집계와 위임 확대는 별도로 다룹니다.

**구현 중 에이전트가 정한 것**

- 빌드에서 쓰던 공개 조회 모듈을 브라우저에서도 재사용했습니다. 서버·토큰·의존성·권한을 추가하지 않았습니다.
- 상시 폴링 대신 화면 열기/버튼에서만 세 API를 요청합니다. 부분 실패를 최신 정상 자료로 취급하지 않습니다.
- 이전 자료를 유지하고 요청 취소를 반영해 늦은 응답이 화면을 덮어쓰지 않게 했습니다.
- 기존 저장본 생성·24시간 경고·최근 100건 한도는 유지합니다.

## 확인해 주세요

이번 변경을 완료하기 위해 추가로 판단할 것은 없습니다. 다음에는 작업별 완료 근거·예상 밖 개입·회귀의 최소 집계를 정하며 현재 위임 정책을 자동 확대하지 않습니다.

## 확인한 것과 못 한 것

| 확인한 것 | 못 한 것 |
|---|---|
| 신규 로더 13개: 닫힌 이슈 반영·403/429·부분/형식/네트워크 실패·직전 자료·취소 | 모든 네트워크 환경에서 공개 API 호출이 항상 성공하는 것 |
| 로컬 Chromium의 저장본→최신 조회→실패 시 유지 흐름, 페이지 오류 0건 | 상세 모바일·디자인·모든 상호작용 |
| 기존 DART 코드·기대값·CI·권한·의존성 유지 | 성과 지표 자동 집계·자동 위험 분류 |

코드·테스트·문서·빌드와 배포 완료 근거는 이슈·PR에 남깁니다. 조회 실패 시 최신으로 오인시키지 않으며 저장본도 없으면 오류로 표시합니다.
