# 평가용 여러 법인 공시 수집

## 한 줄 요약

여러 법인의 사업보고서 원문과 OpenDART 재무제표 수치를 GitHub Actions로 받아 별도 데이터 브랜치에 저장할 수 있게 됐습니다. 다른 법인 평가(이슈 #31)의 준비 단계이며, 아직 실제로 실행하지 않았습니다.

## 지도에서의 위치

처리 흐름 단계의 상태는 바뀌지 않았습니다. 조회 기능이 아니라 평가용 원문을 모으는 도구입니다. 법인·공시 찾기(B)와 원문 수집(C)의 코드를 일부 재사용합니다.

## 무엇이 달라졌나

| 전 | 후 |
|---|---|
| 헬릭스미스 공시 1건만 받을 수 있음 | 종목코드 최대 8개의 사업보고서 원문을 한 번에 받음 |
| 정답을 원문 대조로만 확인 | OpenDART 재무제표 API의 별도·연결 현금 수치를 함께 받아 교차 확인 |
| 이 세션에서 원문을 받을 길이 없음 | Actions가 받은 결과를 `data/dart-filings-실행번호` 브랜치에서 가져옴 |

기본 대상은 삼성전자, 농심, 셀트리온, 카카오, 현대건설, 리노공업의 2025 사업보고서입니다.

## 누가 무엇을 정했나

**사용자가 정한 것**
- 다른 법인 평가를 Actions 수집으로 진행합니다(2026-11-23).
- 결과를 데이터 브랜치에 저장하고, 수집 작업에만 쓰기 권한을 줍니다(A안).
- 대상 법인은 에이전트가 골라 보여주기로 했습니다.

**구현 중 에이전트가 정한 것**
- 대상 법인 6곳과 사업연도 2025. 실행 전에 바꿀 수 있습니다.
- 정정 보고서가 있으면 원본을 받고 정정은 이름만 기록합니다.
- 한 번에 최대 8개 법인, 요청은 1 + 법인당 4회 이하입니다.
- 재무제표 API 값은 교차 확인에만 쓰고, 정답은 원문에서 정합니다.

## 확인해 주세요

1. **대상 법인 6곳이 괜찮은지 봐주세요.** 병합 후 실행할 때 쓰는 기본값입니다. 다른 업종이나 규모를 넣고 싶으면 실행 전에 알려주세요.

## 확인한 것과 못 한 것

| 확인한 것 | 못 한 것 |
|---|---|
| 가짜 응답으로 원본·정정 구분, 현금 행 선택, 법인별 실패 분리, 키 비노출 | 실제 OpenDART 응답 (병합 후 첫 실행에서 확인) |
| 데이터 브랜치 커밋 단계를 임시 저장소에서 재현 | 실제 push와 권한 동작 |
| pytest 183개, 린트·타입·문서 빌드 통과 | 수집한 원문으로 한 추출 평가 (다음 작업) |
