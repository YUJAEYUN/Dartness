# 조회 입력과 날짜 선택 계약

## 한 줄 요약

금액·보유 조회의 공통 입력과 날짜 선택을 코드로 검증합니다. 최신/지정일·한국 실행일·허용 개월을 처리하며 실제 DART 수집·추출과는 아직 연결하지 않았습니다.

## 지도에서의 위치

```mermaid
flowchart LR
    A[조회 조건 입력] --> B[법인·공시 찾기]
    B --> C[원문 수집]
    classDef changed fill:#dbeafe,stroke:#2563eb,stroke-width:3px
    classDef same fill:#f9fafb,stroke:#d1d5db
    class A changed
    class B,C same
```

A가 미구현에서 일부로 바뀌었습니다. 금액·보유의 공통 부분만 검사하며 유형별 금액 조건·사건 기간·사용자 입력 화면은 아직 없습니다. 다른 단계 상태는 바뀌지 않았습니다.

## 무엇이 달라졌나

| 전 | 후 |
|---|---|
| 조회 모드·허용 개월은 문서 합의만 있음 | 잘못된 조합·소수·음수·불리언 등을 코드로 거절 |
| 서버 날짜나 월말 계산에 의존할 위험 | 명시적 실행 시각에서 한국 날짜·달력 허용 구간 계산 |
| 이전 자료 선택은 미구현 | 준비된 날짜 후보에서 범위 내 최신 날짜를 선택하고 원래 요청과 실제 날짜 보존 |

예를 들어 2026-09-30을 요청하고 6개월을 허용했는데 준비된 후보가 2026-06-30뿐이면 그 날짜와 이전 자료 사용 표시를 반환합니다. 허용할 후보가 없으면 날짜·금액 없이 확인 필요를 반환합니다. 날짜를 골랐다는 사실이 공시 내용이나 금액 조건 충족을 증명하지는 않습니다.

## 누가 무엇을 정했나

**사용자가 정한 것**

- 최신 자료/기준일 지정, 개월 선택지·월말 보정·양끝 포함을 사용합니다.
- 직접 입력은 0 이상의 정수 개월이며 0개월은 정확히 일치입니다.
- 실행일은 한국 시간으로 계산하고 임의 최대 개월 수를 두지 않습니다.

**구현 중 에이전트가 정한 것**

- 공통 요청·실행 기록·선택 결과를 불변 객체로 나누고 실행 시각을 명시적으로 받습니다.
- 미래 기준일·잘못된 타입·표현할 수 없는 날짜는 입력 오류로 거절합니다.
- 미결인 사건 계약을 대신 처리하지 않고 금액·보유의 공통 부분만 지원합니다. 법인·항목·범위를 맞춘 후보 생성과 정정 연결은 후속 작업입니다.

## 확인해 주세요

이번 구현을 완료하기 위해 추가로 판단할 것은 없습니다. 다음에는 유형별 조건과 공시 후보의 범위를 정해 실제 수집·추출에 연결해야 합니다. 미결 조건은 코드 기본값으로 넣지 않았습니다.

## 확인한 것과 못 한 것

| 확인한 것 | 못 한 것 |
|---|---|
| 문서의 고정 날짜 예시, 월말·윤년·한국 자정·허용 구간 양끝 | 실제 공시의 날짜 후보 생성·정정 선택·수집 완전성 |
| 신규 날짜 검사 58개를 포함한 Python 292개, 대시보드 40개 | 유형별 금액 조건·전체 법인 검색·엑셀 생성 |
| 린트·타입·문서 strict·생성 일치·빌드, 기존 정답 유지 | 날짜 선택과 추출기를 연결한 운영 흐름 |
