# 정정 전후 현금 셀 비교

## 한 줄 요약

원본·정정 관계와 출처가 맞는 두 현금 셀의 원화 금액을 비교합니다. 같은 값/다른 값은 해당 두 셀에 한하며 최신본이나 최종 적용 값을 선택하지 않습니다.

## 지도에서의 위치

```mermaid
flowchart LR
    A[조회 조건 입력] --> B[법인·공시 찾기]
    B --> C[원문 수집]
    classDef changed fill:#dbeafe,stroke:#2563eb,stroke-width:3px
    class B changed
```

B의 정정 근거 대조를 현금 셀 비교에 연결했습니다. 자동 원문 추출·차수 유효성·정정 적용은 남아 있어 일부 상태를 유지합니다.

## 무엇이 달라졌나

동일 법인·기준일·연결/별도·통화·접수번호·문서 해시·셀 위치를 확인한 뒤 기존 현금 계약의 원화 값을 비교합니다. 관계 보류·값 없음은 확인 필요이고 다른 문서·범위의 값을 섞으면 거절합니다. 단위·원문 숫자·근거를 보존합니다.

## 누가 무엇을 정했나

**기존 docs와 사용자가 정한 것**

- 정정표의 단어만 보고 현금 불변을 추정하지 않고 실제 같은 범위의 두 셀을 대조합니다. 금액이 같아도 자동 최신본 선택으로 바꾸지 않습니다.

**구현 중 에이전트가 정한 것**

- 공통 관계 계약을 재사용하고 첫 비교는 기존 CashValue 계약이 있는 원화 현금으로 한정했습니다. 다른 조회 유형을 현금으로 처리하지 않습니다.
- 관계 상태 문자열만 신뢰하지 않고 원본 입력으로 다시 검사합니다. 기존 현금 값 검증도 다시 실행합니다.
- 단위 변환 뒤 정확한 두 값을 비교하되 반올림 허용치·경고·회사의 오류 기준을 추가하지 않습니다.

## 확인해 주세요

추가 결정은 없습니다. 정정의 의미·인과·최신 유효 차수·최종 적용 값은 이번 두 셀 비교와 구분해 후속으로 남깁니다.

## 확인한 것과 못 한 것

| 확인한 것 | 못 한 것 |
|---|---|
| HD건설기계 개발용 별도·연결 두 셀의 같은 값 재현 | 새로운 공시의 원문 자동 추출·전체 현금 영향 |
| 단위 차이·변형 금액 차이·누락·다른 문서/기간/범위/법인 방지 | 차이의 원인·반올림 허용치·경고 필요성 |
| 관계 근거 보류와 마감 이후는 비교 확정 불가, 기존 후보 보류 유지 | 정정 차수·철회·첨부 병합·최신본 선택 |

목록 행과 변형 금액은 합성/변형 입력이며 실제 변경 정정 사례로 집계하지 않습니다.
