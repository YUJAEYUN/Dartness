# 최신 유효 공시의 현금 자료 선택

상태: 2026-11-26 기존 합의를 재확인해 연결합니다. 정책 원본은 [공통 계약](common-query-contract.md#latest-valid)입니다. 금액이 같은 문서를 합치는 제안은 채택하지 않았습니다.

## 선택 순서

1. 법인 하나의 명시적인 제출일 구간에서 받은 전체 유형 목록을 원시 응답으로 재검사합니다. 월·페이지·요청 파라미터·해시·응답 개수·수집 시점을 대조합니다. complete 문자열만으로 통과시키지 않습니다.
2. 목록의 지원 정기보고서 전체와 받은 ZIP의 접수번호/메타데이터가 정확히 일치해야 합니다. 빠진 원문·추가/중복 원문·읽기 실패가 있으면 확인 필요입니다.
3. 전체 본문에서 법인·서류 코드·표지의 실제 기간/표시 날짜를 확인하고, 명시적 재무상태표의 당기·비교열 날짜·단위·현금 셀을 읽습니다. 분기·반기말과 기말 머리글을 기간 표와 정확히 대응합니다.
4. 요청의 허용 구간에서 가장 가까운 **실제 재무 날짜**를 고릅니다. 그 날짜를 담은 후보 중 **가장 최근 공시 제출일**의 자료를 검사합니다. 금액 일치는 선택 조건이 아닙니다. 최신 유효 값이 과거 공시와 달라도 과거 값으로 되돌리지 않습니다.
5. 선택한 본문의 실제 뷰어 관계 목록과 수집 이력을 대조합니다. 추가/미해결 정정이 없고 원문·목록·본문 관계가 맞아야 사용합니다. 지원 사업보고서 원본/정정 한 쌍이면 기존 전체 XML·정정표·실제 두 셀 대조를 다시 실행합니다.
6. 선택된 원문의 정확한 원화 금액으로 조건을 비교합니다. 실행 기록·기준일·원문 숫자/단위·전체 해시·표/셀 위치·관계와 모든 받은 원문의 기록을 보존합니다.

예: 2025-12-31 지정 조회에서 2026년 분기보고서의 비교열을 사용하더라도 실제 날짜는 2025-12-31입니다. 최신 모드에서는 같은 보고서의 2026-09-30 당기열이 요청 구간에 맞으면 그 날짜를 사용합니다. 문서가 최근이라는 이유로 기준일 밖 날짜를 선택하지 않습니다.

## 보류하는 경우

- 같은 제출일의 서로 다른 최신 후보: 접수번호·입력 순서·금액 일치로 순서를 정하지 않습니다.
- 선택한 원문의 미수집·읽기 실패·잘못된 법인/기간/단위·다른 본문 관계: 오래된 자료로 후퇴하지 않습니다.
- 명시적인 철회/정정명령/제출요구, 정기보고서 첨부정정/첨부추가, 다중 정정, 현재 미지원 분기/반기 정정: 사유를 보존하고 확인 필요로 둡니다. 다른 공시의 일반적인 정정 표시는 선택한 정기보고서의 관계로 임의 연결하지 않습니다.
- 최신 실행일의 이력/본문 관측이 아니거나, 수집 시각이 실행 뒤이거나, 필터·누락·추가 응답이 있으면 성공으로 취급하지 않습니다.

## 코드·결과와 한계

실행은 src/dartness/latest_cash.py의 query_latest_cash입니다. FilingHistory는 src/dartness/filing_history.py에 있으며 받은 실제 응답을 기존 collect_list로 재검사합니다. 기존 select_candidate와 query_cash_reports는 준비된 입력만으로 최신 유효성을 판단하지 못하는 이전 경로로 유지합니다. 기존 기대 정답은 바꾸지 않습니다.

지원 코드는 11011 사업보고서, 11012 반기보고서, 11013 분기보고서입니다. 원문 코드·서류명·공시 제목·표지 기간을 함께 확인합니다. 기존 단일 공시 실행은 기본 사업보고서 프로필을 유지하며 새 실행만 명시적 서류 코드를 전달합니다. 별도/개별/연결 범위는 기존처럼 상위 입력이고 자동 분류하지 않습니다.

결과 run_scope=captured_history_periodic_reports는 **지정한 이력 구간의 지원 정기보고서** 안의 선택입니다. 이 구간 밖 공시·장중 추가 제출·미지원 수시공시의 의미·다른 법인 서식을 모두 확인했다는 뜻이 아닙니다. 수집 시각과 범위를 항상 기록합니다. latest_correction_verified=true는 이 범위의 선택된 보고서 관계 검증이며 전체 시장·모든 정정 유형·공시 수치의 진실성 검증을 뜻하지 않습니다. 내부 selected_report는 기존 지정 문서 추출 결과이므로 그 안의 specified_report_only/false 표시는 그대로입니다.

반환한 CashReportResult는 기존 세 열 엑셀 작성기에 전달할 수 있습니다. 해당 파일은 지정 문서/중간 점검 출력이고 전수 조회 완료로 표시하지 않습니다. 전체 원문 수집·금융업/외화 기준·합계 판정·제품 전수 엑셀·독립 E2E 평가는 남아 있습니다.
