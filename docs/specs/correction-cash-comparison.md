# 정정 전후 현금 셀 비교

기존 [원본·정정 근거 계약](correction-evidence.md)과 [현금 값 계약](cash-query-contract.md)을 연결하는 첫 비교입니다. 공통 관계 검사는 재사용하며 현금 외 항목 비교·사건·원문 자동 추출은 이번 범위가 아닙니다.

## 입력과 검증

원본·정정 관계의 CorrectionAssessment와 각 버전의 CashValue 또는 None을 받습니다. 관계는 공개된 기존 입력으로 다시 assess_correction을 실행해 검사하고, 결과 객체의 status 문자열만 믿지 않습니다. 값이 있으면 기존 CashValue 검증을 다시 실행합니다.

값의 법인·기준일·연결/별도·통화는 그 버전의 후보와 같아야 하고, 키는 cash / cash-and-cash-equivalents / KRW여야 합니다. 문서 접수번호·URL·전체 원문 해시·셀 위치·문맥도 후보 출처와 같아야 합니다. 보고서의 공시일과 실제 재무 기준일은 혼동하지 않습니다. 충돌하거나 다른 항목이면 ValueError이며 미지원 값을 현금으로 변환하지 않습니다.

## 결과와 미확인 경계

관계 보류 또는 어느 버전의 값이 없으면 needs_review입니다. 값 없음은 0이 아닙니다. 두 값이 모두 있고 관계가 metadata_consistent면 검증된 amount_krw를 정확히 비교해 amounts_equal / amounts_differ를 반환합니다. 원문 숫자·단위·출처·관계 입력을 그대로 보존하며 선택된 후보나 최종 적용 값은 반환하지 않습니다.

상이한 단위는 기존 현금 계약의 정확한 원화 변환 후 비교합니다. 표시 반올림 허용치나 차이의 중요도·경고 기준은 새로 정하지 않습니다. amounts_differ는 입력된 두 원화 값이 다르다는 뜻이며 실제 정정의 인과·기업 오류·사용자 경고를 뜻하지 않습니다. amounts_equal도 두 셀의 비교 결과이지 모든 주석·기간·범위의 현금 불변을 뜻하지 않습니다. 입력한 셀 위치/문맥의 실제 의미를 자동 판독하거나 원문 금액 자체를 재추출한 것은 아닙니다.

## 검증 근거

[HD건설기계 개발용 사례](../cases/hd-construction-correction.md)의 2025-12-31 별도 69,787,650,000원·연결 337,873,166,000원은 각 두 버전에서 같습니다. 이미 PDF/XBRL에서 확인한 정답이며 새 출력으로 정답을 만들지 않습니다. 목록 행은 합성입니다. 금액·단위·출처·범위 변경 테스트는 변형 사례로 구분하며 실제 새 정정 사례로 집계하지 않습니다. 기존 복수 후보 보류와 정답 파일은 유지합니다.


## 전체 XML 입력 연결

[전체 원문 바인딩](correction-evidence.md#native-binding)은 사업기간/정정표/웹 관계를 직접 대조하고 실제 두 CashValue를 이 비교에 전달합니다. 이 클래스 자체는 여전히 준비된 입력을 검사하는 책임이며 최신본을 선택하지 않습니다. full_document_binding_verified와 latest_correction_verified를 구분하고, 비교 결과만으로 기업 오류·현금 불변 전체를 판정하지 않습니다.
