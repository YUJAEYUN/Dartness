# 모집단의 현금 조회와 통합 결과

상태: M1에서 기존 모집단·최신 현금 조회·엑셀을 연결하는 일괄 실행입니다. 준비된 모집단과 자료의 실행이며 전수 원문 자동 수집 완료가 아닙니다.

## 입력

같은 한국 실행일의 기존 UniverseSnapshot, 기존 QueryRun, 최소 원화 금액, 조회 범위(법인 자체/그룹 전체), 명시적 최대 처리 법인 수와 법인코드별 준비 자료를 받습니다. 기본 시점·개월 수·금액을 만들지 않습니다. 받은 모집단 전체가 대상이고 법인코드로 연결합니다. 별도/개별은 법인별 상위 확인 입력이며 BS_S만으로 자동 분류하지 않습니다.

명부의 관측 시각·날짜·식별자·시장·중복·출처 해시와 법인별 입력 대응을 검사합니다. 대상 밖 법인의 자료는 거절합니다. 이 소비 단계는 제공된 스냅샷 메타데이터를 검사하며 원시 등록/개황 재수집이나 독립 거래소 명부 검증을 대신하지 않습니다. 준비 자료를 읽는 이번 실행 시각은 관측이 끝난 뒤이며 같은 한국 날짜여야 합니다.

## 처리와 기록

법인코드 순으로 기존 최신 현금 조회를 실행합니다. 금액 순의 영업 우선순위 추천은 하지 않습니다. 각 법인은 확인된 충족·미충족, 확인 필요, 미처리 중 하나로 기록합니다. 준비 자료의 읽기 실패를 전달한 경우에는 확인 필요이며 자료 자체가 없거나 명시한 처리 한도를 넘으면 미처리입니다. 어느 경우도 0원/미충족으로 대체하거나 전체 대상에서 삭제하지 않습니다.

최대 처리 수는 운영 한도이며 금융 조건이 아닙니다. 미처리가 남으면 일부 실행으로 표시합니다. 모든 법인을 시도했어도 확인 필요가 있으면 전체 금액 검증 완료로 표시하지 않습니다. 처리 한도 때문에 모집단 자체를 일부로 바꾸지 않습니다. API 요청 예산·재시도·중간 저장 재개·캐시 삭제 정책은 이번 실행이 결정하지 않습니다. 네트워크를 호출하지 않습니다.

## 출력

내부 JSON에는 전체 명부 식별자/해시·관측 구간·요청 조건·법인별 결과/사유·충족/미충족/확인 필요/미처리 집계를 둡니다. 각 확인 금액은 기존 원문/날짜/범위/단위·금액·정정 근거를 보존합니다.

엑셀은 확인된 충족 법인만 세 열로 합칩니다. 법인명은 현재 모집단의 표시 이름이며 원문에 있던 이름은 내부 기록에 유지합니다. 각 행은 자체의 실제 재무 기준일·별도/개별/연결과 원문 숫자/단위·공시 근거를 보존합니다. 다른 법인의 날짜/단위/범위를 첫 행의 것으로 통일하지 않습니다. 왼쪽 정렬·10포인트·조건 판정 전 표시 반올림 금지를 유지합니다. 표 바로가기가 미확인이면 원래 공시 링크와 메모를 유지합니다.

미처리/확인 필요 법인의 상세 행은 기본 최종 표에 넣지 않되 파일 상단의 집계로 조회 범위를 알립니다. 확인된 충족 법인이 없으면 그렇게만 표시하고 미확인 법인까지 전부 미충족이라고 표현하지 않습니다. 이 출력은 제공 명부/자료의 개발용 실행이며 실제 전체 시장을 조회했다고 하지 않습니다.

## 검증

기존 기대값과 단일 법인 출력의 기본 동작은 유지합니다. 일괄 충족/미충족·자료 누락·한도·범위 충돌·다른 실행일·대상 밖 자료·중복 명부와 두 법인의 서로 다른 원문 단위를 검사합니다. 실제 자료를 다시 쓰는 재현과 합성 모집단/오류를 구분하며 새 독립 평가로 세지 않습니다.

## 실행 API와 확인 내역 옵션

src/dartness/cash_survey.py의 query_cash_survey는 같은 실행일의 UniverseSnapshot, QueryRun, CashScope, 최소 금액, 법인코드별 CashSurveySources 또는 CashSourceFailure와 최대 처리 수를 받습니다. SourceFailure는 읽기 실패 사유만 담으며 금액/성공 상태를 대신 입력하지 않습니다. 자료가 없는 법인과 읽기를 시도했으나 실패한 법인을 구분합니다.

CashSurveySources의 basis는 별도/개별/연결의 명시적 확인 입력이고 history/reports/bodies/pairs는 기존 최신 선택 계약을 그대로 사용합니다. table_section이 있으면 저장한 표 HTML을 기존 대조기에 넣고 직접 링크를 확인합니다. 표 대조 실패는 일반 공시 링크와 미확인 메모로 남기며 확인된 금융 금액을 미충족으로 바꾸지 않습니다. API/웹 요청은 발생하지 않습니다.

write_cash_survey_workbook은 새 통합 작성기와 기존 행/서식 작성기를 공유합니다. 기존 단일 공시·단일 법인 출력의 기본 동작은 유지합니다. 공통 요청·최소 금액이 다르거나 같은 법인을 중복 출력하려는 행은 거절합니다.

기존 include_review=False면 조건 충족 표만 둡니다. True로 명시했을 때만 확인 필요/미처리 법인의 이름·상태·쉬운 사유를 별도 확인 내역 시트에 넣습니다. 정상적인 조건 미충족은 오류가 아니며 확인 필요 시트에 섞지 않습니다. 상세 기술 사유와 출처는 내부 JSON에 유지합니다.

JSON의 all_targets_processed는 제공한 모든 대상에 처리를 시도했다는 뜻이고, all_values_verified는 그 안에서 확인 필요도 없다는 뜻입니다. 둘 다 실제 전체 시장의 원천 누락이나 모든 공시 수치의 진실성을 보증하지 않습니다. 명부의 원시 응답 재검증은 기존 수집기의 책임이고 이번 소비 단계는 준비된 메타데이터를 검사합니다.

## 개발용 재현

이미 읽은 동진쎄미켐·HD건설기계의 저장 이력/원문과 표 HTML을 새로 수집하지 않고 재사용했습니다. 실행일 명부를 새로 관측한 실험이 아니며 **합성 명부 메타데이터**에 두 실제 개발용 법인과 미준비 합성 대상을 넣었습니다. 이 재현을 실제 전수 실행이나 새 독립 평가로 세지 않습니다.

| 구분 | 실제 재무 날짜 | 별도 현금 원화 값 | 원문 단위 | 결과 |
|---|---|---|---|---|
| 동진쎄미켐, 기존 실제 자료 | 2026-09-30 | 166,741,090,356원 | 원 | 500억원 조건 충족 |
| HD건설기계, 기존 실제 자료 | 2026-09-30 | 134,070,870,000원 | 천원 | 500억원 조건 충족 |
| 미준비 합성 대상 | 없음 | 없음 | 없음 | 미처리, 금액/엑셀 법인 행 없음 |

총 대상 3·충족 2·미충족 0·확인 필요 0·미처리 1과 all_targets_processed=false를 확인했습니다. 통합 엑셀은 실제 값이 확인된 두 법인만 담았으며 각 원문/직접 표 링크·단위 메모·숫자·10포인트/왼쪽 정렬을 재열어 대조했습니다. 다른 날짜/단위/개별 범위의 혼합, 자료 누락/읽기 실패/한도, 별도/연결 충돌, 다른 관측일, 중복 명부와 확인 내역 옵션은 tests/test_cash_survey.py의 합성/변형 사례입니다. 기존 금액 정답은 바꾸지 않았습니다.

## 남은 범위

아직은 메모리의 준비된 스냅샷/법인별 자료를 연결하는 개발자 API입니다. 수천 법인의 원문 자동 확보·수집 요청 예산·캐시·중간 재개·파일 기반 명부 로딩/최종 사용자 입력·프로덕션 공유/보관 정책은 구현하지 않았습니다. 미지원 금융업/외화/첨부·철회/다중 정정과 주석 합계도 기존 보류를 유지합니다.
