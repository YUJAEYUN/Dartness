# 공통 공시 목록 수집

상태: 2026-11-24 공통 수집의 첫 구현 계약입니다. 제출된 문서의 목록과 출처를 모으며 자산 보유·금액·정정 적용 여부를 판단하지 않습니다.

## 공식 API 근거

[OpenDART 공시검색 가이드](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001)를 확인했습니다. list.json은 법인코드가 없으면 검색기간을 3개월로 제한하고 페이지당 최대 100건을 제공합니다. last_reprt_at=N은 정정보고서를 포함한 전체 제출 보고서를 검색합니다. 정기공시 외 주요사항·기타·외부감사·거래소 공시 등의 유형도 같은 API를 사용합니다.

## 입력과 처리

입력은 시작/종료 제출일, 선택 법인코드·법인구분·공시유형입니다. 재무 기준일이나 현금 조건을 입력으로 대신 쓰지 않습니다. 호출자는 양수의 최대 API 요청 횟수를 명시해야 합니다. 이 예산은 작업량 한도이며 사용자 조회 개월의 상한이 아닙니다.

기간은 달력 월말 기준의 비중첩 구간으로 나눕니다. 한 구간은 한 달 이하라 법인코드가 없는 경우의 3개월 제한 안에 있습니다. 3개월씩 묶는 최적화보다 월말·윤년·경계의 검증을 우선하며 요청 수가 더 많을 수 있습니다. 시작/종료일은 포함하고 다음 구간은 전 구간 다음 날부터 시작합니다. 12월 9999년 같은 날짜 상한에서도 넘치는 날짜를 만들지 않습니다.

각 구간은 page_count=100·접수일 오름차순·last_reprt_at=N을 고정하고 모든 페이지를 받습니다. 필터는 모든 구간·페이지에 그대로 전달합니다. 자동 재시도·병렬 호출은 추가하지 않습니다. 호출자가 기존 fetch_bytes를 인증키가 결과에 남지 않는 함수로 주입합니다. 목록 함수는 키를 받거나 보관하지 않습니다. 기존 fetch_bytes의 고정 공식 주소·시간/크기 제한·키 보호를 사용하며 기존 평가용 수집기는 수정하지 않습니다.

## 완료와 실패

페이지 번호·크기·총 건수·총 페이지·행 수를 검사하고 구간 안에서 메타데이터가 변하면 실패합니다. 응답의 법인·시장·제출일이 요청 범위와 다르거나 접수번호 등 필수 필드가 잘못돼도 실패합니다. 보고서명에서 공시유형이나 실제 재무 기준일을 추정하지 않습니다.

접수번호로 결과를 병합합니다. 같은 접수번호의 내용이 다르면 충돌로 실패합니다. 같은 구간에서 중복 때문에 고유 건수가 API 총 건수보다 작아져도 누락 가능성으로 실패합니다. 중복을 지웠다는 이유만으로 전체 수집 완료라고 표시하지 않습니다. 상태 013은 해당 구간의 자료 없음이며 정상 오류·한도·인증 실패와 구분합니다.

어느 구간/페이지든 실패하거나 요청 예산을 넘으면 성공 결과나 부분 목록을 반환하지 않습니다. 고정된 안전 오류 코드로 실패하고 앞에서 모은 일부 목록을 전체 결과로 사용하지 않습니다. 성공 결과는 요청 범위·실제 요청 횟수·정렬된 공시 목록을 보존합니다. 각 항목은 접수번호·법인코드/이름/구분·종목코드·공시명·제출일·제출인·비고와 접수번호로 만든 DART 원문 링크를 담습니다. 인증키·상위 API 메시지는 결과에 넣지 않습니다.

## 지원 범위와 한계

공식 응답의 페이지 완전성을 검사하지만 API가 검색 중 바뀌지 않는 시점 고정 스냅샷을 제공한다고 보증하지 않습니다. 같은 총 건수로 내용이 바뀌는 등 관측할 수 없는 누락까지 증명하지 못합니다. 실제 과거 조회 가능 범위를 기간 분할로 확장하거나 복원하지 않습니다.

법인코드 없는 검색은 전체 공시 대상 검색이지 실행일 현재 상장법인 전수조사가 아닙니다. [실행일 상장법인 연결](listed-universe.md)에서 공식 등록파일·현재 기업개황의 모집단을 연결합니다. 독립 거래소 명부/실제 API 전수 대조·재무 기준일 후보 생성·정정 연결·원문 다운로드·추출·금액 비교·엑셀은 후속입니다. 기본 테스트는 공식 필드 계약을 이용한 합성 고정 응답입니다. 실제 API를 전수 실행하거나 실제 추출 정답을 검증했다고 표시하지 않습니다.
