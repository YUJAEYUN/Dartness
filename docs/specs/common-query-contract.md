# 공통 조회·시점·출력 계약 초안

상태: 2026-11-23 사용자 선택을 정리했습니다. 아래는 합의한 정책과 입력·결과 계약의 초안이며 Python 금액·보유 조회의 공통 입력·실행 기록·날짜 선택 계약을 구현했습니다. [저장 현금 원문 연결](cash-report-slice.md#report-candidates)은 기간 후보·선택·금액·엑셀을 제한적으로 지원합니다. 전수 조회·최신 유효 정정 적용은 아직 미완료입니다. 유형별 범위는 [조회 유형](query-types.md), 구현 수준은 [시스템 상태](../system-status.md)를 봅니다.

## 공통 입력 계약의 방향

| 필드 | 의미와 현재 결정 |
|---|---|
| 조회 유형 | 다섯 유형 중 하나. 미구현 유형을 현금 조회로 대신 처리하지 않음 |
| 법인 범위 | 기본은 실행일 현재 상장법인 전체와 세 시장. 지정 목록으로 좁히는 기능의 구체 형식은 후속 설계 |
| 조회 시점 | 금액·보유 상태는 최신 자료 또는 기준일 지정. 어느 모드도 임의 기본 선택하지 않음 |
| 요청 기준일 | 기준일 지정 모드에서 명시. 최신 모드의 계산 기준은 실행일이며 공시 제출일과 구분 |
| 대상 기간 | 사건 조회에서 명시할 시작·종료 범위. 주식보상·대출의 어떤 사건을 볼지는 유형별 미결 유지 |
| 최대 경과 기간 | 정확히 일치, 3개월, 6개월, 12개월, 직접 입력 중 선택. 직접 입력도 개월 단위이며 계산은 아래 규칙 적용 |
| 유형별 조건 | 금액·통화·자산 범위·당사자 역할 등 유형별 계약으로 검증. 아직 없는 기준을 채우지 않음 |
| 검토 내역 포함 | 기본은 끔. 켜면 확인 불가 법인과 이유를 별도 시트로 제공 |

입력은 한 유형을 명시하는 구조로 시작합니다. AND/OR 복합 조건·자동 유형 추론·모듈 등록 방식은 아직 구현하지 않았습니다. 같은 법인의 중복 상장·종목과 법인 식별을 구분해야 하며, 전수조사의 기준은 법인입니다. 모집단은 조회 실행일 현재 상장법인이며 요청한 과거 재무 기준일 당시의 상장 목록을 복원하는 방식은 기본으로 사용하지 않습니다.

## 조회 시점과 허용 기간

금액·보유 상태 조회는 다음 두 모드 중 사용자가 선택합니다. 사건 조회의 시작·종료 기간과 사건 의미는 별도 설계 대상입니다.

| 모드 | 계산 기준 날짜 | 선택할 자료 |
|---|---|---|
| 최신 자료 | 조회 실행일 | 실행일까지 공개된 자료 중 허용 기간 안에서 실제 자료 기준일이 가장 최근인 자료 |
| 기준일 지정 | 사용자가 지정한 기준일 | 해당 날짜 자료를 우선하고 없으면 허용 기간 안에서 가장 가까운 이전 자료 |

최신은 가장 최근에 제출된 문서를 뜻하지 않습니다. 최근 공시에 실린 과거 비교 수치와 최신 실제 기준일을 구분합니다. 두 모드 모두 지정한 재무 범위·항목·통화가 맞아야 하며 실행일까지 공개된 관련 최신 유효 정정을 적용합니다.

허용 기간은 정확히 일치 / 3개월 / 6개월 / 12개월 / 직접 입력으로 제공합니다. 직접 입력도 개월 수입니다. 시스템이 3·6·12개월 중 하나를 미리 선택하거나 자료를 못 찾았다고 기간을 늘리지 않습니다. 정확히 일치는 계산 기준 날짜와 실제 자료 날짜가 같아야 한다는 뜻입니다. 따라서 최신 모드에서 정확히 일치를 선택하면 실행일 당일 자료만 허용하며, 없으면 확인 필요입니다.

개월은 고정 일수가 아닌 달력 기준입니다. 계산 기준 날짜에서 선택한 개월 수를 한 번에 빼고, 해당 월에 같은 날짜가 없으면 그달 말일로 맞춥니다. 허용 구간은 시작일과 계산 기준 날짜를 모두 포함합니다. 매월 반복 차감해 날짜가 줄어들거나 월말을 무조건 유지하는 방식은 사용하지 않습니다.

| 계산 기준 날짜 | 사용자 선택 | 허용되는 실제 자료 날짜 |
|---|---|---|
| 2026-09-30 | 6개월 | 2026-03-30 ~ 2026-09-30 |
| 2026-08-31 | 6개월 | 2026-02-28 ~ 2026-08-31 |
| 2024-08-31 | 6개월 | 2024-02-29 ~ 2024-08-31 |
| 2026-09-30 | 정확히 일치 | 2026-09-30만 |

예시는 달력 규칙을 설명하는 가상 날짜이며 실제 공시 추출 정답이 아닙니다. 예를 들어 첫 행에서는 3월 30일은 허용하고 3월 29일은 허용하지 않습니다. 직접 입력은 0 이상의 정수 개월이며 0개월은 정확히 일치입니다. 소수·문자열·불리언·음수는 변환하지 않고 거절합니다. 실행일은 시간대가 있는 실행 시각을 한국 시간(Asia/Seoul)으로 바꾼 날짜입니다. API 요청 한도를 사용자 허용 개월의 상한으로 쓰지 않습니다. Python 날짜로 표현할 수 없는 허용 시작일은 계산 오류로 거절하고, 임의의 최대 개월 수나 시작일로 바꾸지 않습니다.

## 공시 검색 기간과 API 요청 범위

자료의 허용 기간은 표 안의 실제 자료 기준일을 제한합니다. 공시 검색 기간은 제출된 문서를 찾기 위한 별개 범위입니다. 최근 공시에 과거 수치가 들어갈 수 있으므로 두 범위를 같은 것으로 취급하지 않습니다. 과거 기준일 뒤에 제출됐더라도 실행일까지 공개된 관련 자료는 후보가 될 수 있습니다.

공시 검색 범위가 한 번의 API 요청 한도를 넘으면 해당 API의 공식 제한에 맞춰 기간을 나눠 조회합니다. 각 구간의 모든 페이지를 받고 접수번호 등 문서 식별자로 중복을 제거한 뒤 관련 원본·정정을 연결해야 합니다. 일부 구간이나 페이지가 실패하면 전체 검색을 완료했다고 표시하지 않습니다. 기간 분할이 제공되지 않는 오래된 자료를 복원해 주는 것은 아닙니다.

[공통 공시 목록 수집](disclosure-list.md)에 공식 list.json 제한과 월 분할·페이지 검증을 구현했습니다. API 응답 범위의 목록 수집이며 [실행일 상장법인 모집단](listed-universe.md)은 공식 등록파일과 현재 기업개황을 연결했고, 정정 연결·후보 의미 판정은 아직 연결하지 않았습니다. 과거 조회 가능 범위를 기간 분할로 확장하지 않으며 일률적인 사용자 최대 개월 수를 만들지 않습니다.

## 시점 선택과 결과에 남길 것

재무 기준일은 공시 안의 표가 나타내는 날짜이고 공시일은 그 정보를 공개한 날짜입니다. 기준일 뒤에 공시된 보고서도 실행일까지 공개됐다면 사용할 수 있습니다. 요청 기준일 뒤의 재무 금액을 가져와 과거 기준일 금액으로 쓰지는 않습니다.

선택 대상은 요청한 재무 범위·항목과 맞는 자료입니다. 날짜가 맞아도 별도·연결이나 통화·항목이 다르면 대신 채우지 않습니다. 기준일 지정 모드는 해당 날짜 자료가 없을 때 허용 범위 안에서 가장 가까운 이전 기준일을 선택하고, 최신 모드는 실행일을 상한으로 가장 최근 실제 기준일을 선택합니다. 경과 범위를 지정하지 않았거나 정책이 모호하면 임의 한도로 실행하지 않습니다. 미래 자료·한도 밖 자료를 자동 대체하지 않습니다.

이전 자료를 선택하면 다음을 함께 보존하고 필요한 항목은 기본 결과에 표시합니다.

- 선택한 조회 모드·계산 기준 날짜와 실제 자료 기준일, 지정 모드의 사용자 요청 기준일
- 이전 자료 사용 여부와 선택 이유
- 선택한 허용 기간·계산된 허용 시작일
- 원문 금액·단위·통화·재무 범위와 근거 위치
- 사용한 공시 식별자·공시일·문서 버전과 정정 반영 여부
- 조회 실행 시각과 적용한 공시 마감

정정 연결의 공식 근거·검증 계획은 [원본·정정공시 조사](../design/correction-linking.md), 전체 PDF·원문 XBRL·변경 전후 고정 정답은 [개발용 사례](../cases/hd-construction-correction.md)에 있습니다. 동일 법인·보고서 연결 확인과 조회 항목에 대한 변경 영향 확인을 나누며, 제목·제출일·최종본 필터만으로 대체하지 않습니다. 원본 연결이나 항목 적용이 모호하면 기존 복수 후보 보류를 유지합니다.

정정은 조회 대상 수치와 관련된 최신 유효 내용을 사용합니다. 제목에 정정이라는 말이 있다는 것만으로 다른 기간이나 다른 보고서를 덮어쓰지 않습니다. 원본과 정정본의 연결·해당 항목의 변경 범위·버전을 확인하는 구현이 필요하며, 아직 해당 엔진은 없습니다.

## 현금 계약 v1과의 관계

사용자 요청의 기준일과, 추출할 표의 선정된 기준일을 구분합니다. 예를 들어 사용자가 2025-12-31을 요청하고 허용 범위 안에서 2025-09-30 자료를 선정했다면, 추출에 전달하는 CashQuery.as_of는 실제 표의 2025-09-30입니다. 상위 실행 기록에는 원래 요청일 2025-12-31과 대체 사용 사실을 따로 남깁니다.

CashValue.as_of와 CashQuery.as_of는 여전히 같아야 합니다. 기존 다른 날짜 거절 테스트와 원문 정답은 유지합니다. 이는 실제 금액의 날짜를 바꿔 표시하지 못하게 하는 경계입니다. [저장 현금 원문 연결](cash-report-slice.md#report-candidates)이 날짜 선택 결과를 기존 추출기에 전달합니다. 추출 함수 자체가 과거 자료를 임의 선택하도록 바뀐 것은 아니며 전수 운영 엔진은 아직 미완료입니다.

기존 CASH-003은 이 날짜 혼동 금지로 적용합니다. 사용자가 허용한 이전 자료 선택을 명시적으로 기록하는 것과, 다른 시점을 요청 시점의 금액으로 위장하는 것은 구분합니다.

## 최종 파일과 내부 검증 기록

최종 엑셀은 연락할 법인을 추리는 결과물입니다. 기본 시트에는 조건 충족을 확인한 법인과 필요한 금액·사실·기준일·근거 링크를 담습니다. 이때 연락 우선순위 점수나 영업 제안을 자동 생성하는 정책을 추가한 것은 아닙니다.

확인 불가를 조건 미충족이나 0원으로 취급하지 않습니다. 기본 시트에서 제외하더라도 내부 기록에 법인·이유·확인 경로·실패·원문·남은 확인을 남깁니다. 사용자가 검토 내역 포함을 선택하면 이를 같은 파일의 별도 시트에 제공합니다. 옵션을 켜지 않아도 감사·재검증용 내부 기록을 지우지 않습니다. 조건을 충족하지 않은 정상 결과와 확인 불가를 내부 집계에서도 구분합니다.

실제 자료 기준일과 이전 자료 사용 여부는 대상 판단에 영향을 주므로 기본 결과에서도 숨기지 않습니다. 근거 링크와 정정 여부도 사용한 사실을 대조할 수 있게 표시합니다. 현금의 세 열·원문 메모·표시 형식과 근거 표 링크는 [출력 예시](output-example.md)와 [지원 실행](cash-report-slice.md)을 따릅니다. 다른 유형의 추가 항목과 최종 전수 결과 검증은 후속입니다.

## 아직 정할 것과 구현하지 않은 것

- OpenDART 모집단의 실제 전수/독립 원천 대조·등록정보 갱신 지연/누락 확인(코드·해시·관측 시각·법인 통합은 listed-universe 계약에 구현)
- list.json 외 API별 제한 확인과 상장 모집단·수집 실행 전체의 완전성 검증
- 최초 보고서와 정정의 연결 방법, 해당 항목이 변경되지 않은 정정·여러 동률 후보 처리
- 사건 기간의 경계와 보상·담보대출의 구체 조회 대상
- 유형별 자산 범위·환율·평가 기준·금액 비교·조건 판정
- 다른 조회 유형의 출력 세부 항목, 최종 전수 엑셀 검증, 내부 기록의 저장 방식·보관 기간

평가용 수집기가 정정 전 원본을 보존하는 것은 회귀·대조 자료 수집 목적입니다. 이번 운영 결과 선택 정책과 구분하며, 그 수집기의 동작이나 기존 테스트 정답을 조용히 바꾸지 않습니다. 실제 수집·선택·판정·출력 구현은 계약과 사례를 준비한 뒤 연결합니다.

## Python 공통 계약 v1

이번 구현은 금액·보유 상태 조회의 **공통 부분**입니다. src/dartness/query_contract.py와 tests/test_query_contract.py가 담당합니다. 이 공통 객체 자체는 유형별 금액 조건·대상 자산·재무 범위를 담지 않으며, 이것만으로 전체 조회를 실행할 수 없습니다. 현금의 한정된 연결은 [지원 실행](cash-report-slice.md#report-candidates)을 봅니다. 사건 기간·주식보상·주식담보대출 요청을 금액 조회로 바꾸지 않습니다.

| 객체·함수 | 필드·역할 |
|---|---|
| SnapshotRequest | query_type=cash/try-assets/us-bonds, mode=latest/as_of, 필수 max_age_months, 선택 as_of, include_review=False, contract_version=snapshot-v1 |
| QueryRun | request, 필수 시간대 포함 executed_at, 계산된 execution_date·anchor_date·earliest_date. 모집단 날짜는 execution_date이며 공시 마감의 실행 시각도 보존 |
| SelectedDate | run, actual_date, status=selected, 자동 계산 is_prior. 실제 날짜는 허용 구간 안이어야 함 |
| DateNeedsReview | run, status=needs_review, reason=period_unavailable. 실제 날짜·금액 없음 |
| select_date(run, candidates) | 같은 법인·항목·범위·통화에 맞게 준비한 날짜 후보 중 허용 구간 내 최댓값을 반환. 없으면 DateNeedsReview |

모드·개월 수에는 기본값이 없습니다. latest에는 as_of를 넣지 않고, as_of 모드에는 날짜만 넣습니다(datetime·문자열은 거절). 지정 기준일이 한국 실행일보다 미래이면 아직 도래하지 않은 기준일이므로 거절합니다. include_review는 불리언만 허용합니다. executed_at을 생략하거나 시간대 없이 전달해 서버 시간대를 암묵적으로 쓰지 않습니다. 유효하지 않은 입력은 ValueError이며, 누락된 필수 생성자 인자는 Python의 TypeError입니다.

실행 기록과 결과는 불변 데이터 객체입니다. 실행 기록의 날짜는 입력에서 계산하며 외부에서 별도 지정할 수 없습니다. SelectedDate를 직접 만들더라도 한도 밖 날짜는 거절합니다. 선택 결과의 is_prior는 실제 자료 날짜가 anchor_date보다 이전인지를 뜻하며 최신 모드에서도 표시합니다. 최종 출력에는 모드·계산 기준 날짜·실제 자료 날짜를 함께 사용해야 합니다.

이 함수는 공시를 읽거나 문서·정정을 선택하지 않습니다. 날짜 중복은 같은 날짜로 처리하되 동일 날짜의 여러 문서 중 하나를 임의로 고르지 않습니다. 아래 공시 후보 계약은 명시된 법인·항목·범위·통화 키의 일치를 검사합니다. 실제 원문에서 키를 판정하는 책임과 수집 완전성 확인은 상위 단계에 있습니다. 저장 현금 원문의 기간/단위/현금 근거는 제한적으로 연결했으며 범위 자동 판정·수집 완전성 확인은 후속입니다. 날짜 선택 성공을 공시 사실·조건 충족으로 표시할 수 없습니다. 선택된 날짜만 기존 CashQuery.as_of에 전달할 수 있고 원래 요청과 실행 기록은 함께 보존해야 합니다.

## 공시 후보 계약 v1

이슈 #52의 범위는 src/dartness/disclosure_candidate.py와 tests/test_disclosure_candidate.py입니다. 아래 구조·기대 동작을 먼저 문서와 테스트에 적은 뒤 구현했습니다. 기존 날짜 계산 코드와 수집기·현금 추출기·평가 정답은 수정하지 않습니다.

|---|---|
| CandidateKey | corp_code=8자리 DART 법인 코드, query_type=cash/try-assets/us-bonds, item_key·basis=비어 있지 않은 명시적 식별 문자열, currency=대문자 영문 3자리 |

item_key와 basis는 상위 단계가 실제 근거에 맞게 명시해야 하는 식별자입니다. 예를 들어 cash-and-cash-equivalents와 separate를 사용할 수 있지만 이 값들만으로 다른 자산의 분류 체계를 확정한 것은 아닙니다. 별도·개별·연결을 자동으로 동등 취급하지 않습니다. 통화는 표기 형식만 검사하며 실제 통화·항목·법인 소유 관계는 원문 대조가 필요합니다. document_id는 비어 있지 않은 원문 식별자이며 URL·해시와 같은 문서인지까지 온라인 검증하지 않습니다.

### 거절·선택·확인 필요

- 요청이나 후보의 필수 값·타입·출처 형식이 잘못되면 ValueError입니다. 후보의 법인·조회 유형·항목·범위·통화가 요청과 하나라도 다르면 섞인 입력 전체를 거절합니다. 다른 법인의 값으로 대체하거나 후보를 조용히 삭제하지 않습니다.
- 실행일 이후 공시된 후보는 선택하지 않습니다. 공시일은 한국 실행일과 비교하는 날짜이며, 당일의 정확한 공개 시각은 이 계약만으로 확인할 수 없습니다. 원래 후보와 공시일은 내부 결과에 남깁니다.
- 공시 마감에 맞는 후보의 실제 기준일을 기존 select_date에 전달합니다. 가장 가까운 허용 날짜가 없으면 period_unavailable이며 candidate는 없습니다. 금액·조건 미충족을 뜻하지 않습니다.
- 선택한 날짜에 후보가 하나면 원문 식별자·해시·링크·위치·문맥을 바꾸지 않고 반환합니다. 모든 필드가 같은 후보의 단순 반복만 중복으로 취급합니다. 원래 입력에는 반복도 그대로 보존합니다.
- 선택한 날짜에 서로 다른 후보가 둘 이상이면 ambiguous_candidate로 보류합니다. 최신 공시일·접수번호·입력 순서로 하나를 고르거나 오래된 날짜의 단일 후보로 후퇴하지 않습니다. 서로 다른 원문 위치도 임의로 합치지 않습니다.
- 결과의 후보·상태·사유·날짜 선택은 입력에서 계산합니다. 외부에서 성공 상태나 특정 후보를 별도 지정할 수 없습니다. 내부 결과에는 원래 요청·실행 기록·전체 후보를 보존합니다. 최종 엑셀에 그대로 넣는 형식은 아닙니다.

| 먼저 고정한 합성 사례 | 기대 결과 |
|---|---|
| 2026-09-30 요청·6개월 허용, 2026-06-30 후보 한 건 | 실제 날짜 6월 30일·이전 자료 표시와 동일한 출처 보존 |
| 다른 법인 또는 연결·통화·항목·유형이 섞임 | 입력 오류; 다른 후보로 자동 대체하지 않음 |
| 같은 9월 30일의 서로 다른 두 문서·원본/정정 후보 | ambiguous_candidate, 단일 candidate 없음, 두 원문 보존 |
| 같은 후보가 두 번 들어옴 | 단일 후보 선택 가능, 원래 후보 목록은 두 건 유지 |
| 9월 30일 후보 두 건과 6월 30일 단일 후보 | 9월의 모호함으로 보류, 6월로 후퇴하지 않음 |
| 요청 범위 밖 날짜 또는 실행일 뒤 공시만 존재 | period_unavailable, 선택 후보·금액 없음 |

이 예시는 합성 메타데이터 테스트입니다. 사실 검증이나 실제 공시 추출 평가가 아닙니다. status=selected는 제공된 후보 중 날짜와 식별 범위가 맞는 한 건이라는 뜻이며 공시 내용·정정 완전성·금액 조건 충족을 확정하지 않습니다. 지원 현금 원문의 후보 생성·기존 CashQuery/추출기 연결은 아래 실행 경로를 사용합니다. 범용 보고서 의미 판정과 별도/개별 자동 판정은 아직 없습니다. 동일 날짜의 여러 후보를 해결할 정정 연결 규칙도 후속입니다.


## 저장 현금 원문과의 첫 연결

[지정 공시 실행의 기간 후보 연결](cash-report-slice.md#report-candidates)은 제공된 원문 묶음에서 날짜·현금 근거를 생성해 이 계약을 재사용합니다. 준비된 메타데이터만 검사하던 선택기에 실제 지원 원문의 기간별 후보를 전달합니다. 공시 전체 수집 완전성·최신 유효 정정 선택·상위 단계가 제공하는 별도/개별 판정은 여전히 후속입니다. 위 날짜/동률 정책과 기존 예시는 바꾸지 않습니다.

2026-11-26 사용자가 다시 확인했습니다. 같은 실제 재무 날짜가 여러 공시에 있으면 **조회 실행일까지 공개된 최신 유효 공시**를 사용합니다. 값이 같아야만 묶는 정책은 채택하지 않았습니다. 먼저 허용된 실제 재무 날짜를 선택하고, 그 날짜를 담은 공시 중 검증된 최신 제출본을 선택합니다. 비교열의 날짜를 해당 보고서의 당기 날짜로 바꾸지 않습니다.

기존 공시 후보 v1의 복수 후보 보류는 근거 없이 받은 메타데이터만으로 최신 유효성을 판정하지 못하는 기본 동작입니다. 이 기본 선택기와 기존 정답은 유지하며, 전체 유형 이력·실제 원문·본문 관계·필요한 정정 근거를 확인하는 상위 실행에서 최신본을 선택합니다. 금액 일치는 최신성 근거가 아니며 검증된 정정 금액의 변경 자체가 실패는 아닙니다. 동일 제출일의 서로 다른 문서는 접수번호로 순서를 추정하지 않습니다. 더 최신인 자료의 미수집·읽기 실패·미해결 정정은 과거 자료로 숨기지 않습니다.

첫 연결은 지정한 한 법인의 수집 기간 안에 있는 지원 정기보고서와 명시적인 본문 관계를 대상으로 합니다. 모든 법인/수시공시·분기/반기 정정·다중 정정·철회 해석을 완료했다고 표현하지 않습니다. 미지원 관계는 사유와 원문을 보존하고 확인 필요로 둡니다. 전수 수집·독립 E2E는 별도입니다.
