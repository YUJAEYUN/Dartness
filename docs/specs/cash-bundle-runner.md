# 저장 수집 자료의 조회 실행

상태: 이슈 #108의 개발자 실행 경로입니다. 기존 수집 산출물과 [최신 현금 선택](latest-cash-source.md)을 연결하며 최종 비전공자용 입력 형식을 정하는 문서가 아닙니다.

## 입력과 책임

- 한 법인의 filing_history 수집 폴더와 annual/exact_receipts 원문 수집 폴더들을 명시합니다. 전체 유형 목록의 원시 응답·해시·파라미터·시각을 재검사하고, 원문 ZIP/모든 멤버/본문의 선언 해시·크기를 대조합니다.
- 원문은 요청 법인 및 이력의 정기보고서와 정확히 대응해야 합니다. 누락·추가·중복·다른 법인·해시 불일치를 임의로 무시하지 않습니다. 현재 개발자 경로는 단일 법인 수집 묶음입니다.
- 기존 요청 필드(모드·최대 경과 개월·선택 기준일·법인 코드·명시적 재무 범위·최소 원화 금액)와 시간대 있는 실행 시각을 받습니다. 임의 기본 시점/한도/금액은 없습니다.
- 본문 HTML의 접수번호·파일·실제 관측 시각을 명시합니다. 정정을 적용하려면 기존 CorrectionPair/CorrectionWebInputs에 대응하는 원시 파일과 메타데이터도 받습니다. 성공 상태나 준비된 금액을 입력받지 않습니다.

수집 폴더 내 파일 경로는 그 폴더를 벗어날 수 없습니다. JSON/응답/원문/웹의 기존 크기 제한을 유지하며 인증키는 읽거나 필요로 하지 않습니다. 수집 기록의 items/complete만 믿지 않고 원시 응답으로 다시 만든 목록을 사용합니다.

## 실행·출력

개발자 CLI는 저장 파일만 읽습니다. 새 API/웹 요청이나 대규모 조사는 수행하지 않습니다. 선택과 보류는 기존 query_latest_cash에 맡기고 별도 판정 기준을 만들지 않습니다. 선택 금액이 있으면 기존 지정 문서 엑셀 작성기로 연결하며 범위·요청/실제 날짜·원문 숫자/단위·실패와 검증 기록을 JSON에 남깁니다.

저장한 재무상태표 HTML도 제공하면 기존 링크 대조를 실행합니다. 없거나 대조에 실패하면 일반 공시 링크·표 바로가기 미확인 메모를 유지합니다. 금액을 0이나 미충족으로 바꾸지 않습니다. 출력은 개발용/지정 이력 범위이며 제품 전수 결과로 표시하지 않습니다. 현금 미선정은 법인 금액 행을 만들지 않고 JSON에 사유를 남깁니다.

원문 영구 저장·자동 삭제·보관 기간·공유 저장소·전수 API 예산·최종 사용자 템플릿은 이 실행 경로가 결정하지 않습니다. 생성 결과는 Git 자동 커밋/푸시 대상이 아닙니다.

## 검증 기준

기존 실제 개발용 및 추가 법인 평가의 날짜·접수번호·원화 금액을 재현합니다. 테스트 정답을 실행 결과에서 새로 만들지 않습니다. 잘못된 경로/해시·중복/누락·다른 법인·일관되지 않은 목록 선언·미지원 상태는 성공 금액으로 바뀌면 안 됩니다. CLI를 통해 JSON·엑셀까지 재현하고 네트워크를 호출하지 않는지도 검사합니다.
