# 현재 상장 모집단과 제한된 현금 원천 실행 연결

상태: 기존 기준을 유지하는 연결 계약입니다. 실제 대량 호출은 실행 예산을 확인한 뒤 진행합니다. 기존 [모집단](listed-universe.md)·[일괄 조회](cash-survey.md)·[최신 선택](latest-cash-source.md)이 정책 원본입니다.

## 입력과 순서

기존 SnapshotRequest, CashScope·정확한 원화 최소 금액, 명시적 제출일 검색 시작일, 전체 API/웹 예산, 처리 법인/원문 상한을 받습니다. cash 외 유형을 현금으로 대신 실행하지 않습니다. 입력 금액을 시범값 500억원으로 고정하지 않습니다.

먼저 기존 collect_universe가 실행일의 등록 ZIP과 모든 후보 기업개황을 확인합니다. 세 시장 누락·기업개황 실패·불충분한 명부 예산이면 전체 명부를 완료한 것으로 반환하지 않습니다. 처리할 원문 법인을 2개로 제한해도 명부 작성에 수천 회가 필요할 수 있습니다. 과거 명부를 오늘 명부로 표시하거나 일부 명부를 전체 명부로 합성하지 않습니다.

첫 연결은 최대 10개 법인과 법인당 최대 8개 정기보고서를 처리하는 제한 실행입니다. 상한은 운영 보호이며 금융 조건이 아닙니다. 지정한 대상 코드가 없으면 법인코드 순으로 처리 한도만큼 고르고, 검증용으로 명시한 대상 코드가 있으면 전체 명부에 속하는지 확인해 사용합니다. 이 순서는 영업 우선순위나 금융 조건에 따른 순위가 아닙니다. 어떤 경우든 나머지 전체 명부는 한도 미처리로 남습니다.

별도/개별/연결은 법인별 확인 입력을 받습니다. 지정한 전체 재무 범위와 맞지 않거나 확인 입력이 없으면 사유를 보존하고 금액을 추정하지 않습니다. 별도/개별 자동 판정 모듈이 이미 있다고 가정하지 않습니다. 모든 법인의 범위를 사용자가 수작업으로 입력해야 한다는 제품 요구사항을 확정한 것도 아닙니다.

각 대상의 전체 유형 공시 이력을 기존 월 분할/전체 페이지 수집기로 받습니다. 지원 정기보고서 원문 전체가 원문 상한을 넘으면 일부만 골라 최신 자료라고 하지 않고 보류합니다. 기존 지정 원문 수집의 2건 제한은 작은 묶음으로 재사용하며 완화하지 않습니다. 전체 원문과 본문 관측을 기존 최신 선택에 전달하고 선택된 자료의 표를 대조한 뒤 일괄 조회·공통 엑셀을 재사용합니다.

## 시간·한도·결과

하나의 명시적 API 예산에 명부·목록·원문을 모두 포함하며 실패한 요청도 셉니다. 웹 예산은 별도로 셉니다. 자동 재시도·동시 호출·다른 날짜 캐시는 추가하지 않습니다. 소수 E2E 전용 재사용 정책을 전수 명부에 자동 확대하지 않습니다.

명부 작성 시작과 최종 조회는 같은 한국 날짜여야 합니다. 최종 조회 시각은 수집 완료 뒤로 기록해 실제 관측 시각을 미래 입력처럼 조작하지 않습니다. 자정을 넘으면 같은 날짜의 실행 결과를 만들지 않습니다. 공시 검색 종료일은 실행일이며 재무 기준일/허용기간과 혼동하지 않습니다.

내부 결과는 전체 명부·대상 선택·실제 요청 수·실패·미처리·조건 충족/미충족을 보존합니다. 선택한 법인의 자료/기준 미확인은 확인 필요이고 선택하지 않은 법인은 한도 미처리입니다. 둘 다 0원이나 조건 미충족으로 바꾸지 않습니다. 확인된 충족만 기존 세 열 엑셀로 출력합니다. 일부 실행을 전수 금액 검증 완료로 표시하지 않습니다.

## 검증과 남은 결정

우선 합성 명부에서 실제 수집과 동일한 콜백 경로로 계약을 검사합니다. 합성 결과를 실제 전수 실행으로 세지 않습니다. 최근 실제 전체 명부 실행은 약 40분/4천 회였으므로 새 실제 실행에는 명부 요청과 추가 원문 요청을 포함한 예산을 확인해야 합니다.

현재 단계는 개발자 API 연결이며 실제 전체 시장의 현금 검증·범위 자동 확인·금융업/외화·모든 정정·주석 합계·독립 추출 평가·최종 사용자 템플릿 완료가 아닙니다. 제한 실행의 명부 예산·범위 확인 모듈·독립 평가 수용 기준은 실제 근거와 함께 후속 논의합니다.

## 개발자 API

UniverseCashPlan은 기존 SnapshotRequest, 재무 범위·정확한 최소 금액·제출일 시작일, API/웹/처리 수/원문 상한과 법인별 확인된 재무 범위를 받습니다. target_codes가 비어 있으면 법인코드 순으로 고르고, 지정하면 검증용 대상 창으로 사용합니다. collect_universe_cash에 공식 API/웹 콜백을 명시해 실행합니다. 생성된 plan만으로는 요청하지 않습니다. 결과 survey를 기존 write_cash_survey_workbook에 전달하면 전체 집계와 충족 법인 엑셀을 만듭니다. 결과에는 선택 코드·실제 API/웹 시도 수·표 링크 확인 실패와 원천 객체도 남습니다.

이 연결은 원본/정정 쌍의 추가 웹 근거를 자동 수집하지 않습니다. 기존 최신 선택이 쌍 근거를 요구하면 확인 필요를 유지합니다. 표 바로가기 실패는 기존처럼 원래 공시 링크/사유를 유지합니다. 공개 평가용 수동 실행 어댑터와 원격 원천/진행 기록 보관을 연결했습니다. 전수 배치/명부 중간 재개와 실제 예산 검증은 후속입니다. 이 단계에서 4천 회의 네트워크 호출은 하지 않았습니다.

## 실제 실행용 수동 어댑터

기존 Collect DART filings의 universe_cash 모드는 universe_cash_config에 아래처럼 명시한 JSON과 history_start를 받습니다. 공개 예제/공개 조건의 개발자 검증 전용이며 실제 고객 목록·내부 조건·비공개 결과를 이 공개 데이터 브랜치에 저장하지 않습니다. 제품의 최종 비전공자 입력 템플릿은 아닙니다. 금액은 부동소수점 입력을 피하기 위해 정확한 원화 문자열로 받습니다. CLI에서는 불필요한 대량 호출을 막기 위해 확인된 재무 범위가 있는 명시적 검증 대상이 필요합니다. 일반 개발자 API의 전체 명부 보존/기본 대상 선택 기준을 바꾸지는 않습니다.

```json
{
  "mode": "latest",
  "max_age_months": 12,
  "scope": "standalone",
  "minimum_krw": "50000000000",
  "max_api_requests": 5000,
  "max_web_requests": 20,
  "max_companies": 2,
  "max_reports_per_company": 8,
  "basis_by_corp": {"00118804": "separate", "01205842": "separate"},
  "target_codes": ["00118804", "01205842"]
}
```

시작일 예시는 2026-03-18이고 종료일은 실제 한국 실행일입니다. 예제는 기존 개발용 두 법인의 연결 검사이며 새 독립 평가로 세지 않습니다. 이 입력을 문서화한 것이 실제 실행 승인이나 실행 완료를 의미하지 않습니다. 요청 수와 시간의 실제 한도를 확인한 뒤 실행합니다.

이 모드만 전체 처리 3,000초(50분)·종료 유예 5초·Actions 잡 60분 상한을 씁니다. 다른 기존 수집 모드의 한도는 바꾸지 않습니다. 진행 기록은 기업개황 50건마다, 원문/목록/웹 응답과 실패 시에도 남깁니다. 기업개황 원문 연락처/대표자 등은 저장하지 않고 요청·응답 해시만 기록합니다. 공개 등록 ZIP·목록/원문·웹은 기존 인증키 검사 뒤 보존합니다. 완료되면 전체 명부 상태 JSON과 합의된 세 열 엑셀을 씁니다. 부분 실패/중단은 완성된 명부나 전수 금액 성공으로 표시하지 않습니다. 전체 취소·러너 종료·원격 push 실패 때 원격 보관까지 보장하지 않으며, 수집 중이던 회사 응답과 명부 계산 중간 상태를 직접 재개하는 기능도 아직 없습니다.

기존 시크릿·의존성·contents 권한과 별도 data 브랜치를 재사용합니다. 새 상시 실행·자동 재시도·캐시 정책·외부 DART 래퍼는 없습니다. 실제 대량 API 호출은 이번 구현/CI에서 하지 않았습니다.
