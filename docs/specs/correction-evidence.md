# 원본·정정 연결 근거의 입력 계약

상태: 기존 [연결 조사](../design/correction-linking.md)의 첫 구현입니다. 준비한 근거의 식별자·범위·시점 정합성을 검사하며 관계 자동 발견·근거 문장의 진실성·최신본 선택·항목 적용은 하지 않습니다. 기존 복수 후보 보류를 유지합니다.

## 입력과 책임

- 원본/정정 각각 기존 DisclosureCandidate와 수집 목록의 Disclosure를 받습니다. 접수번호·법인코드·제출일이 같아야 합니다. 목록 제목이나 rm으로 관계를 확정하지 않습니다.
- 각 버전의 서류 종류·사업기간은 원문에서 확인해 입력합니다. 후보의 실제 자료 날짜가 그 기간 안에 있고, 두 버전의 전체 CandidateKey·종류·사업기간이 같아야 합니다. 이 첫 계약은 사업기간이 있는 재무 조회용입니다. 사건·첨부/철회·다중 차수는 포함하지 않습니다.
- 정정표의 최초 제출일과 근거 위치는 정정 전체 원문의 CandidateSource로 받습니다. 정정 후보와 문서 ID·공시일·전체 해시·URL이 같아야 합니다. 위치·주변 문장은 정정표를 가리키며 후보 셀 위치와 달라도 됩니다.
- 공식 뷰어의 명시적 원본·정정 접수번호 관계는 별도 ViewerRelation으로 받습니다. 접수번호 두 개·DART URL·응답 SHA-256·위치·문맥을 보존합니다. 이 해시는 뷰어 응답 해시이며 전체 PDF/XML 해시로 대신 쓰지 않습니다.

## 검증과 결과

목록/후보나 근거 식별자가 충돌하는 입력은 ValueError입니다. 원본과 정정의 법인·항목·범위·통화·종류·사업기간, 정정표 최초 제출일과 원본 공시일, 뷰어 관계의 두 접수번호를 대조합니다. 같은 날 순서 불명·실행일 뒤 정정·근거 누락은 needs_review로 남깁니다. 준비된 근거가 모두 맞으면 metadata_consistent입니다. 이 상태는 관계 원문을 자동 판독했다거나 적용 가능한 최신 정정/현금 불변을 확정한 결과가 아닙니다. 결과에 원본 입력·근거·이유를 보존하고 선택된 후보나 금액은 반환하지 않습니다.

## 검증 사례

[HD건설기계 개발용 사례](../cases/hd-construction-correction.md)의 원본 20260318001192·정정 20260602000456, 2025 사업기간·2026-03-18 최초 제출일을 사용합니다. 전체 PDF 해시와 뷰어 응답 해시는 각각 기존 기록에서 가져옵니다. 기존 사례·정답을 수정하지 않습니다. 법인/기간/접수/최초일/근거 충돌은 실제 값을 변경한 사례로, 근거 없음·같은 날·마감 이후는 합성 사례로 구분합니다. 통과 사례가 다른 보고서의 정정 의미를 증명하지는 않습니다.
