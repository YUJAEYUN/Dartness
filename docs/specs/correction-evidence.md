# 원본·정정 연결 근거의 입력 계약

상태: 기존 [연결 조사](../design/correction-linking.md)의 첫 구현입니다. 준비한 근거의 식별자·범위·시점 정합성을 검사하며 관계 자동 발견·근거 문장의 진실성·최신본 선택·항목 적용은 하지 않습니다. 기존 복수 후보 보류를 유지합니다.

## 입력과 책임

- 원본/정정 각각 기존 DisclosureCandidate와 수집 목록의 Disclosure를 받습니다. 접수번호·법인코드·제출일이 같아야 합니다. 목록 제목이나 rm으로 관계를 확정하지 않습니다.
- 각 버전의 서류 종류·사업기간은 원문에서 확인해 입력합니다. 후보의 실제 자료 날짜가 그 기간 안에 있고, 두 버전의 전체 CandidateKey·종류·사업기간이 같아야 합니다. 이 첫 계약은 사업기간이 있는 재무 조회용입니다. 사건·첨부/철회·다중 차수는 포함하지 않습니다.
- 정정표의 최초 제출일과 근거 위치는 정정 전체 원문의 CandidateSource로 받습니다. 정정 후보와 문서 ID·공시일·전체 해시·URL이 같아야 합니다. 위치·주변 문장은 정정표를 가리키며 후보 셀 위치와 달라도 됩니다.
- 공식 뷰어의 명시적 원본·정정 접수번호 관계는 별도 ViewerRelation으로 받습니다. 접수번호 두 개·DART URL·응답 SHA-256·위치·문맥을 보존합니다. 이 해시는 뷰어 응답 해시이며 전체 PDF/XML 해시로 대신 쓰지 않습니다.

## 검증과 결과

목록/후보나 근거 식별자가 충돌하는 입력은 ValueError입니다. 원본과 정정의 법인·항목·범위·통화·종류·사업기간, 정정표 최초 제출일과 원본 공시일, 뷰어 관계의 두 접수번호를 대조합니다. 같은 날 순서 불명·실행일 뒤 정정·근거 누락은 needs_review로 남깁니다. 준비된 근거가 모두 맞으면 metadata_consistent입니다. 이 상태는 관계 원문을 자동 판독했다거나 적용 가능한 최신 정정/현금 불변을 확정한 결과가 아닙니다. 결과에 원본 입력·근거·이유를 보존하고 선택된 후보나 금액은 반환하지 않습니다.

## 검증 사례

[HD건설기계 개발용 사례](../cases/hd-construction-correction.md)의 원본 20260318001192·정정 20260602000456, 2025 사업기간·2026-03-18 최초 제출일을 사용합니다. 전체 PDF 해시와 뷰어 응답 해시는 각각 기존 기록에서 가져옵니다. 기존 사례·정답을 수정하지 않습니다. 법인/기간/접수/최초일/근거 충돌은 실제 값을 변경한 사례로, 근거 없음·같은 날·마감 이후는 합성 사례로 구분합니다. 통과 사례가 다른 보고서의 정정 의미를 증명하지는 않습니다.

## 실제 웹 근거를 읽는 첫 연결

본문 관계와 정정표의 메타데이터를 사람이 다시 입력하던 부분을 저장된 공식 DART HTML에서 읽습니다. 양쪽 `select#family`의 법인·선택된 본문 접수번호·본문 목록의 날짜/보고서 종류/정정 표시를 대조합니다. `select#att`와 통합 문서 선택은 본문 관계 증거로 사용하지 않습니다. 목록 순서로 부모나 최신본을 결정하지 않으며 추가 본문도 삭제하지 않고 보존합니다.

정정표는 명시적인 정정 제목 아래의 대상 서류·최초 제출일·정정일과 변경 항목/사유/정정 전후를 표 셀에서 읽습니다. 서로 다른 첫 제출일·누락/중복/병합 셀·바뀐 웹 형식은 지원 성공으로 처리하지 않습니다. 임의 문장을 LLM으로 보충하거나 정정 항목에 현금이 없다는 이유로 현금 불변을 판정하지 않습니다.

출력은 웹에서 관측한 관계/정정표 정보와 응답별 해시·관측 시각입니다. HTML 구간 해시를 기존 CandidateSource의 전체 원문 해시로 바꾸어 넣지 않습니다. 현재 PDF/XBRL 전체 원문과의 바인딩·사업기간/실제 항목 영향·전체 이력/유효 차수 판정은 다음 연결이며 이 관측만으로 CorrectionAssessment를 통과시키거나 현금 후보를 선택하지 않습니다. 기존 동률/정정 미확인 보류는 유지합니다.


실행은 src/dartness/correction_observation.py의 observe_correction_web(저장 응답 대조) 또는 collect_correction_web(양쪽 본문·정정표 최대 3회 순차 요청)입니다. 수집 함수는 전달받은 공식 웹 전송 함수를 사용하며 API 키·추가 권한·무제한 재시도는 없습니다. 요청/전송 실패를 정상 빈 결과로 바꾸지 않습니다. 일반 PR CI는 저장 응답을 사용하고 실시간 DART를 호출하지 않습니다.

정정표 주소는 정정 본문의 실제 목차에서 구합니다. 받은 정정표의 출처 URL이 이 주소와 같아야 하며, 다른 구간의 HTML을 이 정정표로 연결하지 않습니다. 공통 목차 읽기는 src/dartness/dart_viewer.py에서 재사용하며 기존 현금 표 바로가기도 같은 위치 검사를 사용합니다. 재무상태표 URL·기존 기대값은 유지합니다.

관측 결과는 web_evidence_observed입니다. 원래/정정 뷰어의 전체 본문 목록·정정일·최초 제출일·변경 문구·응답 해시·관측 시각·원문 링크를 보존합니다. 추가 버전이 있어도 조용히 삭제하지 않고 모든 본문 항목을 남기며 선택한 접수번호는 없습니다. 양쪽 목록의 내용이 다르거나 중복 본문·법인/날짜 충돌·바뀐 정정표 구조는 오류입니다. 출력의 full_document_binding_verified, cash_impact_verified, latest_correction_verified는 모두 false입니다.

HD건설기계의 기존 공식 저장 응답(2026-11-23 관측)을 tests/fixtures/corrections/hd-viewer-observation에 원본 바이트 그대로 압축 보존했습니다. 기존 연구 기록의 해시·수동 대조 정답과 일치하며 새 관측이나 미사용 검증용이 아닙니다. tests/test_correction_observation.py는 실제 개발용 대조와 변형/합성 실패를 구분합니다. 모든 법인·공시 유형이나 최신 이력 완전성을 검증한 것은 아닙니다.
