# 지정 공시 한 건의 현금 조건 실행

M1의 첫 체크포인트입니다. [상위 목표](https://github.com/YUJAEYUN/Dartness/milestone/1)는 실행일 현재 상장법인 전수·사용자 금액 조건·근거 포함 엑셀입니다. 이 체크포인트는 지정된 공시 원문 ZIP에서 표 구간을 자동 선정하고 현금 금액을 비교하는 경로이며 전수/최신 유효 정정 선택 완료가 아닙니다.

## 입력과 지원 범위

기존 Disclosure·CashQuery, 명시적 CashBasis·확인 시각·0 이상의 정확한 원화 최소 금액을 받습니다. 별도/개별 기본 정책은 유지하며 basis는 상위 단계가 확인해 전달합니다. 별도와 개별을 DART 표 태그만 보고 자동 구분하지 않습니다.

원문은 기존 read_archive의 크기/중복 제한을 거칩니다. 본문은 접수번호와 정확히 같은 이름의 XML 하나이며 첨부 XML을 대신 읽지 않습니다. 첫 지원은 UTF-8 사업보고서(ACODE 11011)의 DOCUMENT·COMPANY-NAME 법인 식별과 TABLE-GROUP ACLASS {XBRL}BS_S 또는 {XBRL}BS_C입니다. 해당 구역이 없거나 중복·중첩·미완성이면 확인 필요입니다. 모든 공시가 이 형식이라는 뜻은 아닙니다.

원문 전체가 일반 XML 문법에 맞지 않는 실제 공시가 있어 HTMLParser로 명시적 구조를 읽습니다. 원문을 자동 보정하거나 정규식으로 첫 금액을 고르지 않습니다. 선언된 외부 엔티티/DOCTYPE는 지원하지 않습니다. 원본 바이트 SHA-256과 UTF-8 텍스트의 구역 위치·구역 해시를 구분해 보존합니다. 기존 표 추출기는 선택 구역의 날짜·단위·행/열·범위를 검사합니다.

## 조건과 결과

CashValue가 나오면 정확한 amount_krw >= min_amount_krw를 비교합니다. 조건은 표시 반올림 값으로 비교하지 않습니다. 값 없음·추출 실패·지원하지 않는 구조는 needs_review이며 조건 미충족이나 0원이 아닙니다. 네트워크/ZIP 오류도 원인을 기록하며 다른 문서로 대체하지 않습니다.

결과는 document_match / document_non_match / needs_review이며 항상 run_scope=specified_report_only, latest_correction_verified=false입니다. 지정 문서의 금액 조건 비교이지 최종 법인 선정 자격은 아닙니다. 법인·공시·요청/실제 날짜·범위·원문 숫자/단위·전체/구역 해시·표/셀 위치·출처·실패 이유를 남깁니다. 최종 제품용 엑셀에는 이 체크포인트 결과를 최신 자료 선정 완료로 섞지 않습니다.

## 실제 사례와 검증

대한약품 원본 20260318001361의 전체 ZIP은 기존 공개 데이터 브랜치 data/dart-filings-45114584895에 보존돼 있습니다. 이 법인은 기존 계정명 수정에 사용한 개발용이며 미사용 검증용이 아닙니다. 기존 cases.json에 원문 대조로 고정한 2025-12-31 개별 현금 43,972,786,132원을 재사용합니다. 500억원 조건은 이 문서에서 미충족, 400억원 조건은 충족입니다. 기존 정답·기대값은 바꾸지 않습니다. 단위·기간·법인·구역 중복/첨부·조건 경계 실패는 합성/변형 사례로 구분합니다.

## 실행·출력 준비

첫 실행은 저장된 공개 원문을 사용해 API 호출 없이 확인합니다. 결과 JSON과 사람이 읽는 엑셀 미리보기는 제품 최종 양식과 구분합니다. 2026-11-25 사용자가 openpyxl와 types-openpyxl 추가를 승인했습니다. requirements.txt의 고정 실행 의존성과 requirements-dev.txt의 타입 스텁을 기존 CI 설치 경로로 연결합니다. 실행하면 JSON과 같은 이름의 XLSX를 함께 작성합니다. 지정 공시 출력 완료가 M1 전수/최신본 적용 완료는 아닙니다.

## 재현 명령과 엑셀 의존성 제안

개발자 체크포인트 실행 예시입니다. 실제 checked-at은 시간대가 있는 실제 확인 시각을 입력하며, 아래 날짜는 고정 재현용입니다. 사용자용 최종 입력 UI를 CLI로 확정한 것은 아닙니다.

PYTHONPATH=src python -m dartness.cash_report --archive tests/fixtures/cash/report-slice/023910.zip --corp-code 00113128 --company-name 대한약품 --receipt 20260318001361 --published-on 2026-03-18 --as-of 2025-12-31 --basis individual --minimum-krw 50000000000 --checked-at 2026-11-25T00:00:00+09:00 --output work/cash-report/result.json

2026-11-25 PyPI 메타데이터에서 openpyxl 3.1.5(MIT, Python 3.8 이상)와 types-openpyxl 3.1.5.20261122(Python 3.10 이상)를 확인했습니다. 작업 환경에 이미 있던 openpyxl로 미리보기 파일 생성·재열기·숫자 셀·근거 링크·수식 없음만 확인했습니다. 프로젝트 의존성으로 추가하지 않았으며 Excel 데스크톱 렌더링 확인은 아닙니다. 이후 사용자 승인으로 openpyxl 3.1.5와 types-openpyxl 3.1.5.20261122를 고정 추가했습니다. openpyxl의 실행 의존성 et_xmlfile 2.0.0도 고정했고 기존 검사와 권한은 유지합니다. 타입 스텁은 기존 mypy strict를 유지하기 위한 개발 의존성입니다.

## 간결한 엑셀과 신뢰 근거

사용자 요청에 따라 기본 표는 법인명·현금 금액(억원)·조회 기준 세 열입니다. 조회 기준에는 실제 재무 기준일과 별도/개별/연결을 함께 표시합니다. 회사명은 공시 원문 링크이고 금액 메모에는 원문 숫자·단위·정확한 원화 값·공시일을 둡니다. 해시·구간 위치·실패 내역은 JSON 기록에 남기며 기본 표를 복잡하게 만들지 않습니다.

조건을 충족한 지정 공시 값만 행으로 내보내고, 미충족/확인 불가는 법인 행이나 0원으로 넣지 않습니다. 대신 결과 없음/확인 필요를 구분해 표시합니다. 최신본·전수 검증이 미완료라는 이 체크포인트의 한계는 파일 상단에 유지합니다.

억 단위 표시는 소수 둘째 자리이며 저장 숫자와 메모의 원화 값은 보존합니다. 표시 반올림은 금액 조건 판정이나 공시의 오차 허용 기준에 사용하지 않습니다. Excel 숫자 셀의 15자리 정밀도 등을 넘으면 원문을 조용히 바꾸지 않고 작성 오류를 반환하며 먼저 저장한 JSON은 남깁니다. 텍스트는 수식으로 실행되지 않도록 명시적으로 기록합니다. 실제 Excel 데스크톱 표시·원문 사실의 진실성을 파일 작성 성공만으로 증명하지 않습니다.

실행 책임은 src/dartness/cash_report.py, 결과 기록은 src/dartness/cash_report_result.py, 파일 작성은 src/dartness/cash_workbook.py로 나눠 순환 참조를 만들지 않습니다. 출력 테스트는 tests/test_cash_workbook.py입니다. 설치는 python -m pip install -r requirements-dev.txt로 기존 검사까지, 실행만 필요하면 requirements.txt를 사용합니다.

2026-11-25 사용자 서식 요청: 제목·머리글·본문·링크를 모두 왼쪽 정렬·10포인트로 통일하고 Excel 눈금선을 표시합니다. 셀 내용·금액·근거 링크·메모를 삭제하지 않습니다.

사용자의 후속 참고 양식에 맞춰 흰 바탕·상단 조회 정보 한 줄·2행 굵은 머리글·3행부터 데이터·기본 행 높이·A3 틀 고정/필터로 정리합니다. 왼쪽 정렬·10포인트·눈금선·세 열과 근거는 유지합니다. 참고 파일의 회사/팀/분류 내용은 사용하지 않습니다.

## 근거 표 바로가기

2026-11-25 사용자 요청으로 법인명은 확인된 재무상태표 구간으로 바로 연결합니다. 접수번호·법인·범위가 맞는 DART 본문 목차에서 문서 ID·요소·위치·길이를 읽고, 해당 구간을 실제로 열어 원문 추출값의 날짜·단위·금액과 대조합니다. 주소 인자는 문서별로 읽으며 예시 값을 재사용하지 않습니다. 목차의 제목만 보고 검증 완료로 처리하지 않습니다.

직접 링크는 표가 있는 구간을 엽니다. 현금 행 자체의 강조·스크롤이나 DART 웹 인터페이스의 영구 호환성을 보장하지 않습니다. 원래 공시 주소·목차/구간 응답 해시·확인 상태는 JSON에 남깁니다. 원문 전체 해시와 뷰어 응답 해시는 구분합니다. 금액 조건·기준일·정정 선택 정책은 바꾸지 않습니다.

개발자 CLI는 조건 충족 시 공식 DART 웹 뷰어를 조회해 링크를 확인합니다. 재현/오프라인 검증에는 저장한 목차와 구간 HTML을 한 쌍으로 입력할 수 있습니다. 누락·모호한 목차·응답 오류·값 불일치면 직접 링크를 만들지 않고, 공시 전체 링크와 메모의 `표 바로가기 미확인` 표시·JSON의 실패 이유를 보존합니다. 링크 확인 실패는 현금 금액을 0원이나 조건 미충족으로 바꾸지 않습니다.

저장 응답으로 재현하려면 `--viewer-main 목차.html --viewer-section 재무상태표.html`을 함께 지정합니다. 일반 실행은 두 인자를 생략하고 공식 뷰어를 조회합니다. 일반 PR 테스트는 저장한 공개 응답을 사용하며 실제 DART 네트워크 호출을 추가하지 않습니다.

구현은 src/dartness/cash_viewer.py이며 tests/test_cash_viewer.py의 대한약품 개발용 웹 응답과 변형 실패 사례로 검사합니다. tests/fixtures/cash/report-viewer/origin.json의 관측 주소·응답 해시를 보존하며 기존 원문 금액 정답을 유지합니다. 한 보고서의 확인이며 다른 모든 서식·법인의 바로가기를 검증한 것은 아닙니다.

## 저장 공시의 기간 후보와 공통 요청 연결

이슈 #94는 제공된 같은 법인 원문 ZIP 묶음에서 지원 재무상태표의 당기·비교기간을 읽어 기존 CandidateRequest/select_candidate에 연결합니다. 실제 법인 코드는 전체 본문과 대조하고 날짜·단위·현금 행/열은 기존 추출 검사로 확인합니다. 재무 범위는 기존 실행과 같이 상위 단계에서 확인해 전달하며 BS_S만으로 별도/개별을 자동 구분하지 않습니다. 입력으로 준 전체 범위와 판정 근거를 보존합니다.

요청은 기존 QueryRun과 명시적 별도/개별/연결, 법인 코드, 정확한 원화 하한, 저장 보고서 목록입니다. 원문에서 확인한 각 기간의 현금 값과 근거로 후보를 만들고 날짜·마감·동률 처리는 기존 계약을 재사용합니다. 미래 공시는 제외 근거를 남기고 사용하지 않습니다. 동일 후보의 반복만 중복으로 취급하며 같은 날짜의 다른 원문은 보류하고 이전 날짜로 후퇴하지 않습니다.

지원 구역의 모든 비교기간 열을 기존 추출기로 확인합니다. 하나라도 날짜/단위/금액을 확인하지 못하는 지원 밖 입력은 실패 기록을 남기고 묶음 전체를 확인 필요로 둡니다. 읽기 실패 보고서를 조용히 제외해 오래된 자료를 선택하지 않습니다. 이 첫 연결은 비교기간 열 하나의 오류로 전체 보고서가 보류될 수 있는 보수적인 지원 범위입니다.

선택한 실제 날짜로 CashQuery를 만들고 기존 지정 공시 실행에 연결합니다. 요청 모드·요청 기준일·허용 구간·실제 날짜·이전 자료 여부는 내부 결과에 함께 보존하고, 결과 엑셀에도 요청 기준일과 이전 자료 표시를 유지합니다. 준비된 보고서 묶음 안에서의 선택이며 전수 수집 완전성이나 최신 유효 정정 확인을 뜻하지 않습니다. 정정 표시가 있는 단일 문서도 관계/유효성이 확인되지 않았으면 보류합니다. 최신 정정 확인 상태는 계속 false입니다.


### 실행 경로와 확인 범위

src/dartness/cash_report_candidates.py의 StoredCashReport는 공시 목록 메타데이터와 원문 ZIP입니다. read_cash_candidates는 명시적 구역·기간·현금 셀을 확인해 날짜별 근거를 만듭니다. src/dartness/cash_snapshot.py의 query_cash_reports는 기존 QueryRun을 받아 그 후보들을 공통 선택기에 전달하고 선택한 실제 날짜를 기존 inspect_cash_report에 연결합니다. 다른 조회 유형을 현금으로 대신 실행하지 않습니다.

CashSnapshotResult는 전체 후보·입력 출처·제외·실패·선택 결과를 JSON으로 제공합니다. `run_scope=provided_reports_only`이며 공시 목록 메타데이터와 별도/개별 판정은 상위 단계가 제공했다는 사실을 표시합니다. 최종 제품의 법인 선정 자격을 증명하지 않습니다. 읽기 실패는 `source_incomplete`, 선택할 날짜가 없으면 `period_unavailable`, 동률은 `ambiguous_candidate`, 단일 정정 표시의 관계/유효성 미확인은 `correction_unresolved`입니다. 금액을 선택할 수 없으면 selected_report가 없고 엑셀 법인 행으로 출력하지 않습니다.

예를 들어 상위 단계에서 확인한 `run`, `corp_code`, `basis`, `minimum_krw`, `stored_reports`를 전달하면 다음처럼 기존 출력으로 연결할 수 있습니다. 외부 입력 화면이나 새 템플릿 형식을 확정하는 예시는 아닙니다.

```python
snapshot = query_cash_reports(run, corp_code, basis, minimum_krw, stored_reports)
audit = snapshot.to_dict()
if snapshot.report is not None:
    write_cash_report_workbook(snapshot.report, output_path)
```
