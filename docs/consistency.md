# 문서·위키·코드 정합성 검토

상태: 검토 절차의 첫 버전. 의미 비교를 자동 수행하는 프로그램은 아직 없습니다.

프로젝트 기준은 사람이 읽는 docs입니다. 위키는 이를 찾아주는 지도이며, 코드는 기준을 구현합니다. 차이가 생기면 문서를 코드에 자동으로 맞추지 않습니다.

## 세 관계를 확인합니다

| 관계 | 검토 내용 |
|---|---|
| 기준 문서 ↔ 코드 | 조건·예외가 구현됐는가? 명세 밖의 추정·대체 동작이 있는가? |
| 기준 문서 ↔ 위키 | 중요한 조건을 누락하거나 뜻을 바꾸지 않았는가? |
| 위키 ↔ 코드 | 안내한 구현·테스트가 존재하며 설명과 맞는가? |

## 중요한 규칙의 연결

오판·누락·출력 변화에 영향을 주는 규칙에만 안정적인 식별자를 붙입니다. 모든 문장에 번호를 만들지 않습니다. 규칙 원문은 해당 도메인 문서에 두고, 아래 기록에는 참조와 검토 근거를 남깁니다. 폐기한 식별자는 다른 의미로 재사용하지 않습니다.

[검토 기록 양식](record-forms/consistency-review.md)에서 범위, 기준 커밋, 문서 위치, 구현·테스트·위키 위치, 관찰한 차이와 한계를 기록합니다. 존재하지 않는 구현 경로는 만들지 않고 미구현으로 씁니다.

## 검토 상태

| 상태 | 의미 |
|---|---|
| 검토상 일치 | 명시한 버전·범위에서 구현·테스트·위키를 확인했고 차이를 찾지 못함 |
| 불일치 | 구체적인 충돌·누락 발견 |
| 미구현 | 기준은 있으나 구현이 없음 |
| 판단 보류 | 기준이 모호하거나 검증 근거 부족 |
| 재검토 필요 | 관련 기준·구현·테스트·위키가 마지막 검토 이후 변경됨 |

차이가 없다는 관찰과 절대적 정확성을 구분합니다. 링크 존재·테스트 통과만으로 검토상 일치로 승격하지 않습니다. 일부 관계만 확인했다면 각각 구분해 기록합니다.

## 변경과 주기적 검토

PR에서 바뀐 내용과 연결된 규칙을 확인합니다. 문서·위키·코드 중 관련된 다른 쪽을 고치지 않아도 된다면 이유를 짧게 적습니다. 미구현인 동작을 문서에서 삭제해 정합성이 좋아진 것처럼 만들지 않습니다.

관련 파일이 변경되면 사람이든 에이전트든 마지막 확인 버전과 차이를 보고 재검토 필요로 표시합니다. 현재는 이 표시를 자동 갱신하지 않습니다. 정기 검토는 주간 CI 결과를 확인할 때 범위를 정해 수행하며, 실행자·발견 사항·미확인 범위를 기록합니다. 정기 LLM 실행과 자동 PR 생성은 설정하지 않았습니다.

기계 검사에는 파일·링크 존재, 스키마 예시, 테스트 등을 맡기고 의미 검토에는 조건·예외·테스트의 실효성을 맡깁니다. 에이전트는 근거 위치와 수정안을 제시하며, 기준 변경은 필요한 논의를 거칩니다.

## 첫 적용 규칙

<a id="amount-001"></a>
규칙 **AMOUNT-001**: 적용 단위를 확인할 수 없는 금액은 추정하지 않고 확인 필요로 처리합니다.

이 규칙의 원문은 [정확성과 근거](requirements.md#accuracy)에 있습니다. 아래는 문서·위키 연결을 시작하기 위한 현재 상태이며 조회 정확성 검증 결과가 아닙니다.

| 연결 | 현재 상태 | 근거 |
|---|---|---|
| docs ↔ 위키 | 문서 참조 연결, 의미 검토 기록은 PR에 남김 | [금액 처리 안내](wiki/index.md#amount) |
| docs ↔ 코드 | 미구현 | DART 조회 엔진 없음 |
| 위키 ↔ 코드 | 미구현 | 구현 위치를 안내하지 않음 |

예상 확인 사례: 숫자·통화는 있지만 적용 단위가 없고 상위 문맥에서도 확인할 수 없는 입력. 기대 동작은 확인 필요이며 조건 충족으로 확정하지 않는 것입니다. 실제 fixture와 테스트는 다음 구현에서 만듭니다.
