# 상장 명부 속도 개선의 공식 근거와 작은 비교

상태: 2026-11-27 공식 문서 조사. 현재 명부 구성·당일 관측 기준은 유지합니다. 변경된 법인만 재조회하거나 대량 동시 호출을 운영에 적용한 상태가 아닙니다.

## 확인한 사실

| 근거 | 확인한 내용 | 적용 한계 |
|---|---|---|
| [공식 FAQ 목록](https://opendart.fss.or.kr/cop/bbs/selectArticleList.do?bbsId=B0000000000000000002)의 「오픈API 이용한도는 어떻게 되나요?」, 게시글 29, 등록일 2020-01-18 | 개인은 일 20,000건, 기업 등록은 공시검색/기업개황과 나머지 서비스의 한도를 구분해 안내합니다. 분당 1,000회 이상의 과도한 접속은 제한될 수 있습니다 | 실제 키의 등록 구분·개별 설정·남은 한도는 확인하지 않았습니다. 공개 안내만으로 모든 키가 4만 건이라고 확정하지 않습니다 |
| 같은 목록의 「IP 차단 문의는 어디로 해야 하나요」, 게시글 28, 등록일 2020-09-08 | 분당 1,000회 이상 접속에 대한 IP 차단을 안내합니다 | 이보다 적으면 항상 허용된다는 속도 보장이나 동시 요청 허가 수는 아닙니다 |
| [고유번호 개발가이드](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019018)와 [기업개황 개발가이드](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019002) | 제한 오류 020과 개별 설정에 따른 차이를 안내합니다. modify_date는 기업개황정보의 최종변경일자로 설명합니다 | 키별 4만 건 설정을 부정하는 근거는 아니며, 현재 키의 적용값을 조회한 것도 아닙니다 |
| 공식 FAQ 「주요 API서비스별 데이터 반영시점 및 범위는 어떻게 되나요?」, 게시글 25, 등록일 2022-04-21 | 고유번호 변경사항은 익영업일 오전 반영, 공시원본은 제출 후 반영되며 마감일 지연 가능성을 안내합니다 | 고유번호 변경일자만 보고 당일 기업개황/상장 구분이 바뀌지 않았다고 보장할 수 없습니다 |

FAQ 상세는 공식 목록에서 제목을 선택해 POST로 열어 확인했습니다. 상세 GET 링크는 접근 오류가 나므로 목록 주소와 제목/게시글 번호를 함께 남깁니다. 공개 안내는 확인일의 관측이며 개별 인증키 한도를 인증해서 확인한 정보가 아닙니다. 계정 로그인이나 키 추가 발급은 하지 않았습니다.

## 판단

현재 코드의 5,000회는 개발용 한 번의 실행 예산이고, 서비스의 하루 총량과 다릅니다. 하루 허용량을 크게 설정해도 직렬 네트워크 대기 시간이 사라지지 않습니다.

변경일자가 같은 날의 여러 변경을 구분하지 못하고, 변경사항의 반영 지연도 있으므로 당장 전날 기업개황을 오늘 것으로 대신 사용하지 않습니다. 명부 재사용을 바꾸려면 원래 관측 시각·데이터 반영 지연·상장 상태 확인 범위가 명확한 별도 계약이 필요합니다. 이 조사로 기존 조회 기준을 완화하지 않습니다.

## 먼저 할 실험

현재 기준을 유지한 작은 기업개황 응답 속도 비교를 권합니다. 공개 예제 동진쎄미켐/HD건설기계 두 곳만 대상으로 직렬 2건·동시 2건을 두 차례 비교합니다. 총 최대 8회, 동시 최대 2개, 시작 간격 최소 0.5초로 제한합니다. 기관이 이 속도를 보장한다고 주장하지 않으며 키/공유 IP의 다른 사용량도 알 수 없습니다.

오류가 나면 새 요청/다음 단계를 중단하며 자동 재시도하지 않습니다. 이미 진행 중인 최대 두 요청은 종료를 기다립니다. 원문 연락처 등은 저장하지 않고 응답 해시·식별자 일치·시간·오류·최대 동시 수만 기록합니다. 020 등 제한 응답을 우회하지 않습니다.

이 실험은 운영 명부 수집의 순서/선택/검증 기준을 바꾸지 않는 별도 수동 프로브입니다. 실제 4천 회 명부 수집이나 전수 금액 조회는 하지 않습니다. 실측이 끝나도 4천 회의 지연·차단·성공률을 작은 표본에서 단순 추정하지 않습니다. 본 수집의 동시 처리 적용 여부는 별도로 평가합니다.
