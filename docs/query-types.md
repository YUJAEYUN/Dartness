# 올인원 조회 유형

상태: 사용자가 실제로 요청한 다섯 사례를 바탕으로 정리한 첫 명세입니다. 조회 유형과 공통 흐름을 정리하며, 미결 기준은 기본값으로 채우지 않습니다. 현금의 일부 추출만 구현됐고 나머지 유형의 조회·판정은 아직 없습니다.

## 조회 유형별 입력과 결과

이 표는 관리 화면의 조회 유형 카드 원본입니다. '일부'는 현금 계약과 선정된 재무상태표 추출이 있다는 뜻이며 금액 조건으로 전체 법인을 찾을 수 있다는 뜻은 아닙니다. 나머지는 명세 단계입니다.

## 공통 실행 흐름과 분기

요청 유형 확인 → 해당 유형의 입력 계약 검증 → 법인·공시 수집 → 유형에 맞는 근거 후보 탐색 → 코드 검증·판정 → 공통 결과 형식으로 출력합니다. 이 흐름은 설계이며 모든 단계가 실행되는 엔진은 아직 없습니다. 기존 [시스템 상태 지도](system-status.md)는 현금 조회의 첫 실행 경로입니다.

공통으로 재사용할 책임은 법인·문서 식별, 수집, 원문 버전·해시·위치 보존, 표 읽기, 명시된 단위·기간 처리, 실패 기록과 출력입니다. 유형별 책임은 찾아야 할 근거, 관계·역할의 의미, 입력과 결과 계약, 조건 판정입니다. 금액 처리가 필요한 유형에서만 금액·통화·환산 기능을 사용합니다.

에이전트는 조회 유형에 맞는 근거 후보를 찾고 복잡한 문맥을 해석합니다. 코드는 허용된 유형·입력·결과 계약과 실행 순서·계산·실패 처리를 통제합니다. 모듈은 필요한 근거와 판단 방식이 달라질 때 나눕니다. 보고서마다 모듈을 만들거나 거대한 조건문에 모든 정책을 넣지 않습니다. 구체적인 모듈 인터페이스와 등록 방식은 계약을 작성한 뒤 정합니다.

초기 계약 설계안은 한 유형을 명시한 요청부터 작성합니다. 여러 조건의 조합은 사용자 예시를 모아 AND/OR·시점·보유 주체가 같은지부터 정할 설계 항목입니다. 현재 자동 조합이나 유형별 실행 라우터는 없습니다. 이 명세만으로 해당 기능을 지원한다고 표시하지 않습니다.

## 공통 결과 계약의 방향

- 법인과 조회 유형, 요청한 시점/기간·범위·조건을 기록합니다.
- 공시에서 확인한 사실과 조건 충족 판정을 구분합니다. 아직 비교 기능이 없으면 조건을 충족했다고 표시하지 않습니다.
- 금액이 있는 결과는 원문 숫자·단위·통화·평가 기준을 보존합니다. 원화 환산액과 원문 금액을 섞지 않습니다.
- 모든 중요한 사실에 근거 문서·버전·절/표/행/열 또는 문장 위치를 연결합니다. 보상 사실과 증권사 이름은 각각의 근거가 필요할 수 있습니다.
- 확인할 수 없으면 이유·확인한 경로·남은 확인 사항을 기록합니다. 못 찾았다는 사실로 0원·미시행·계약 없음·조건 미충족을 단정하지 않습니다.
- 결과가 많아도 기본 표는 필요한 항목 중심으로 유지하고 세부 근거로 이동하게 합니다. 최종 엑셀 열과 메모 배치는 아직 정하지 않았습니다.

## 유형별로 더 정할 것

**현금:** 기존 [현금 조회 요구사항](requirements.md#cash-scope)과 [계약](cash-query-contract.md)을 유지합니다. 별도·개별 기본은 현금에 합의한 기준이며 다른 유형에 자동 적용하지 않습니다.

**TRY 자산:** 통화가 TRY인 자산인지 확인해야 합니다. TRY 부채, 순외환 노출, 터키 소재 매출·법인이라는 이유로 자산 보유액을 대신하지 않습니다. 원화 500억원 같은 조건을 실행하려면 어떤 자산·평가액·환율·시점을 쓸지 먼저 정해야 합니다.

**미국채권:** 달러 표시 채권이라는 사실만으로 미국채권이라고 판단하지 않습니다. 미국 국채와 미국 회사채 범위, 발행 주체·상품 구성·보유 시점과 평가 기준을 계약에 명시해야 합니다. 펀드 등을 통한 간접 보유 포함 여부도 미결입니다.

**주식보상:** 제도 존재, 부여, 지급/행사, 비용 인식은 서로 다른 사실입니다. 어떤 사실을 찾는지 먼저 정합니다. 보상 사실을 확인했어도 위탁 증권사 이름을 확인하지 못했다면 두 결과를 구분합니다. 공시에 이름이 없으면 다른 거래의 증권사 이름으로 채우지 않습니다.

**주식담보대출:** 법인이 차입하는 경우와 주요주주 등이 자기 주식을 담보로 빌리는 경우의 당사자를 구분합니다. 담보 설정 사실이 대출 실행·현재 잔액을 모두 증명하지는 않습니다. 담보 주식 수를 대출금액으로 바꾸거나 다른 법인의 채무를 합치지 않습니다.

위 항목은 잘못된 대체를 피하기 위한 설계 경계입니다. 세부 계산·조회 정책과 실행 가능한 계약은 유형별로 차례로 정하며 실제 공시 사례로 검증합니다.

## 구현 순서

현재는 유형 명세를 먼저 만들고 대시보드에 구현 범위를 표시합니다. 다음에는 미결 질문 중 한 가지를 정하고 해당 유형의 입력·출력·실패 계약과 실제 공시 사례를 준비합니다. 다른 법인 현금의 첫 평가와 미추출 한계는 [평가 기록](evaluations/cash-table-dart-2025.md)에 있으며 지원 범위 확장은 별도 판단합니다. 기능을 여러 개 동시에 구현하거나 미결 기준을 코드의 숨은 기본값으로 고정하지 않습니다.
